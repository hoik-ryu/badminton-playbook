# Discovery 인터뷰 기록: badminton-playbook

## 아이디어

badminton-playbook이라는 배드민턴 웹 서비스를 기획하려고 합니다.

주요 기능은 복식 로테이션 학습과 동호회 복식 게임 매칭입니다.

MVP 범위는 아직 확정하지 않았습니다.

Discovery 인터뷰부터 시작해 주세요.

## r1 수정 요청 — ASM/Q 확인 (2026-11-06)

사용자가 r1에 대해 "수정 요청"을 선택했습니다. 이어서 "여기서 너가 안물어봐?"라고 요청해, 선택형 질문으로 ASM/Q를 확인했습니다. 아래는 사용자가 고른 선택지입니다.

- Q-004 규칙 우선순위: 공평성 > 중복 회피 > 성별 조합 > 밸런스 (만족할 수 없으면 뒤쪽 규칙부터 완화)
- Q-005 16명 미만 또는 4의 배수가 아닐 때: 가능한 코트 수만큼만 생성하고 남는 인원은 대기, 대기자는 다음 라운드에 우선 배정
- Q-002 자동 대진 수정: 확정 전에 선수 교체나 재생성 후 확정 가능
- Q-001 랭크 산정: 승률 구간별 등급(최소 경기 수 충족자 대상, 구간 기준값은 PRD에서 정함)
- Q-003 권한: 슈퍼 관리자만 운영진 지정·해제 가능, 나머지 운영 기능은 동일
- Q-006 마이페이지: 프로필(이름·성별 등), 본인 랭크·청백전 전적 (선택하지 않음: 학습 진도·퀴즈 결과, 전체 랭킹 보드)
- Q-007 가입·명단: 가입 후 운영진 승인. 필요하면 운영진이 명단에 직접 추가
- Q-008 청백전: 운영진이 청·백 팀과 경기를 편성하고, 경기별 승패만 기록
- ASM 확인: ASM-001, ASM-002·003, ASM-004·005 맞음. ASM-006은 선택하지 않음 → 추가 질문에서 "고정 콘텐츠로 시작"(MVP는 미리 만든 콘텐츠, 편집 기능은 다음 버전)
- Q-009 학습 접근: 로그인한 회원만. 마이페이지에 학습 진도를 고르지 않아 MVP에서는 학습 진도를 저장하지 않는 것으로 정리하겠다고 안내했고, 사용자가 이 선택지를 골랐음
- Q-011 성공 지표: 제안 기본값(런칭 후 1개월간 정기 운동 대진 100%를 서비스로 생성, 같은 날 중복 경기 0건)

## Planning r1 검토 — 가정·미결 질문 확인 (2026-11-06)

사용자 요청: "Planning r1은 아직 승인하지 않겠습니다 … 가정·질문 먼저 확인 방식으로 계속 진행 … 관련 항목끼리 묶어서 선택형으로". 아래는 선택형 질문 5묶음에서 사용자가 고른 답변입니다.

- ASM-007 레벨별: 점수 구간(그룹)별 → 보완 답변: 3구간(상 8–10, 중 5–7, 하 1–4). 인원이 4명 단위로 맞지 않으면 인접 구간에서 점수가 가장 가까운 사람으로 채움
- ASM-008 밸런스: 팀 점수 합 차이 최소(현재 가정 확인)
- ASM-009 성별 조합: 혼복 우선 → 보완 답변: 불가피한 경우에만 불균형 조합을 허용하고 '성별 규칙 완화'로 표시
- ASM-010 공평성: 게임 수 → 직전 대기자 → 참석 체크 순서(현재 가정 확인)
- ASM-011 중복 회피: 파트너 재조합 금지 + 상대 중복 최소화, 동일 경기는 항상 금지(현재 가정 확인)
- ASM-012·013: 시드 재현, 코트 수 설정값 4(현재 가정 확인)
- ASM-014·Q-017: 최소 10경기, S/A/B/C(70/55/40), 전체 누적(현재 가정 확인)
- Q-014 로그인: 카카오 로그인
- Q-015 청백전 게스트: 참가 가능, 회원의 승패만 랭크에 반영
- Q-016 동시 조작: 충돌 감지 + 새로고침
- Q-018 비활성: 운영진이 비활성 처리(참석 목록에서 숨김, 로그인 차단, 기록 유지, 재활성화 가능)
- Q-012 콘텐츠: 기획자가 초안을 만들고 운영진이 검수
- Q-013 지표: 제안 기본값(GOAL-002: 런칭 후 1개월 안에 승인 회원의 50% 이상이 학습 페이지를 1회 이상 방문 / GOAL-003: 청백전 경기의 100%에 승패 기록)
- Q-010 현재 방식: 둘 다 체계적 수단 없음
- Must 재검토: FR-011 중 '수동 교체'만 Should로 낮춤(재생성과 확정은 Must 유지). 나머지 Must는 유지
- 우선순위: FR-013 완화 표시와 신규 '회원 비활성 처리' 모두 Should
