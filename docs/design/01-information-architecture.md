# 정보 구조 (Information Architecture): 배드민턴 플레이북 (badminton-playbook)

> 기준: 기획 r6(승인), UX Planning r4(승인, `00-ux-decisions.md`). 화면 상세(레이아웃·상태 표)는 `02-screens.md`에 있습니다.
>
> **r2 개정(2026-11-13)**: 기획 r6(NFR-001·NFR-002·AC-050, ASM-017 해결)과 UX 결정 r4(UXD-001·002·022·038·066의 r6 정합성, 사용자 결정 D1·D2)를 반영했습니다. 변경안: `docs/workflow-proposals/ux-spec-r2-change-plan.md` X14·Y1·Y2.
> - 회원·운영·인증 화면 모두 PC·모바일 공통 **최대 600px 한 열**(r1: 회원 480px, 운영 PC 넓은 다단 배치)
> - 내비게이션은 PC·모바일 모두 **하단 탭**(r1: 운영 화면 PC 왼쪽 메뉴)
> - 패널은 PC·모바일 모두 **하단 시트**(r1: PC 오른쪽 옆 패널). 형태 `패널(모바일 시트·PC 옆 패널)`은 `시트`로 통합
> - 화면 ID·라우트·접근 역할·플랫폼 값·사이트맵 계층은 바뀌지 않았습니다. r1 원문은 Git 이력과 `design.json`의 `last_approved`(r1 해시)로 확인합니다.

## 1. 역할과 레이아웃 셸

| 역할 | 셸 | 플랫폼 | 근거 |
|---|---|---|---|
| 비로그인 | 인증 셸(탭 없음, 가운데 정렬 한 열) | mobile | FR-001, UXD-016 |
| 계정 제한(승인 대기·거절·비활성) | 인증 셸 | mobile | FLOW-001-S4a, AC-004, AC-058, UXD-013 |
| PER-001 회원 | 회원 셸(하단 탭: 튜토리얼 / 청백전 / 마이페이지). PC에서도 최대 600px 한 열 | mobile | NFR-002, AC-050, UXD-066 |
| PER-002 운영진 | 회원 셸 + '운영' 탭. 운영 화면은 운영 셸(PC에서도 최대 600px 한 열 + 하단 탭) | responsive | NFR-001, AC-003, UXD-001, UXD-047, UXD-066 |
| PER-003 슈퍼 관리자 | 운영진과 같음 + 운영 메뉴에 '역할 관리' | responsive | FR-003, AC-008, UXD-066 |
| PER-004 게스트 | 로그인하지 않음(화면 없음). 명단·대진·청백전의 데이터로만 등장 | - | PRD 페르소나 |

셸 규칙
- **인증 셸**: 로그인, 가입 정보 입력, 계정 상태 안내, 권한 없음, 페이지 없음. 하단 탭 없음.
- **회원 셸**: 하단 탭바 3개(운영진 이상은 4개). 회원 화면은 PC에서도 가운데 정렬한 최대 600px 한 열로 둡니다(UXD-066, AC-050).
- **너비 정책(모든 셸 공통)**: 인증·회원·운영 셸 화면은 PC·태블릿·모바일 모두 같은 한 열 레이아웃을 쓰고, 화면 폭이 600px보다 넓으면 가운데 정렬한 최대 600px 열로 보여 줍니다. 회원 화면은 기획 요구사항(NFR-002, AC-050, ASM-017 해결), 운영 화면은 NFR-001(r6)과 UXD-001·UXD-066(r6 정합성)이 근거입니다. 열 바깥은 배경만 두고 콘텐츠·메뉴를 놓지 않습니다. PC 전용 다단 배치(카드 2열, 옆 패널 동시 표시)와 PC 전용 왼쪽 메뉴는 두지 않습니다(사용자 결정 D1). 정보량이 많은 화면(SCR-112, SCR-223)도 PC에서 넓히지 않고 같은 열 안에서 세로로 쌓습니다.
- **운영 셸**: '운영' 탭 아래 화면. PC·모바일 모두 회원 셸과 같은 하단 탭바를 유지하고, 상단에 운영 화면 제목·뒤로 가기를 둡니다(UXD-066). 패널(참석 체크, 대진 옵션, 회원·게스트 편집, 참가자·팀 구성)은 PC에서도 하단 시트로 엽니다(UXD-002, UXD-022, UXD-038, 사용자 결정 D2). PC 전용 옆 패널·가운데 대화상자 분기는 두지 않습니다. 확인 창(CMP-022)은 시트가 아니라 공통 확인 컴포넌트라 이 규칙과 별개입니다(5장).
- **하단 고정 요소**: 하단 고정 행동 바·주 버튼(예: SCR-211 '게스트 추가')은 600px 열 안에 두고, 하단 탭바와 기기 안전 영역(`env(safe-area-inset-bottom)`) 위에 놓아 서로 가리지 않게 합니다(UXD-026, 사용자 결정 D3). 구체적인 간격 값은 04 3장 공통 패턴에서 정합니다.

## 5. 전역 내비게이션 규칙

- **인증 리다이렉트**: 로그인이 필요한 화면에 비로그인으로 들어오면 SCR-001로 보내고, 로그인 후 원래 주소로 돌아갑니다. 돌아갈 때 그 주소의 접근 권한을 다시 검사해, 권한이 없으면 SCR-004, 계정 제한이면 SCR-003, 없거나 공개되지 않은 청백전이면 '찾을 수 없음'을 보여 줍니다. 원래 주소는 이 서비스 안의 경로만 허용합니다(외부 주소로 보내지 않음). 계정 제한 상태는 어느 화면에서든 SCR-003으로 보냅니다(AC-004).
- **권한 리다이렉트**: 회원이 운영 경로(`/ops/*`)에, 운영진이 `/ops/roles`에 들어오면 SCR-004를 보여 줍니다. 서버도 같은 요청을 거부합니다(AC-009, AC-011). 권한이 없는 메뉴·링크는 처음부터 보여 주지 않습니다.
- **로그인 후 첫 화면**: 돌아갈 주소가 없으면 모든 역할이 첫 번째 탭인 튜토리얼 홈(SCR-101)으로 갑니다. 기획 FLOW-001-S4가 '역할을 확인하고 회원 홈으로 보냅니다. 운영진 이상이면 운영 메뉴도 보여 줍니다'로 정했고, UXD-047(운영진도 회원 탭을 그대로 씀)·UXD-066(탭 순서)과 같습니다. 운영진 이상은 '운영' 탭(승인 대기 배지 포함)으로 한 번에 운영 홈(SCR-201)에 갑니다. 운영진의 첫 화면을 운영 홈으로 바꾸려면 FLOW-001-S4 변경이 필요합니다(PF 대상). 처음 가입하면 SCR-002 → 제출 후 SCR-003(승인 대기).
- **하단 탭**: 탭을 누르면 그 탭의 첫 화면으로 갑니다. 같은 탭을 다시 누르면 그 탭의 첫 화면으로 돌아갑니다. 스테이지 플레이·결과(SCR-102, SCR-103)는 집중을 위해 탭바를 숨기고 상단에 '나가기'를 둡니다.
- **시트**: 시트는 PC·모바일 모두 600px 열 아래쪽에서 올라오는 하단 시트로 부모 화면 위에 열리고(r2, 사용자 결정 D2), 닫기·바깥 누르기·브라우저 뒤로 가기로 닫힙니다. 입력 중인 시트를 닫을 때 저장하지 않은 값이 있으면 확인 창을 띄웁니다(02 상세에서 화면별 정의). 시트 위에 시트가 하나 더 열리는 경우는 SCR-203 → SCR-213/SCR-214, SCR-224 → SCR-214/SCR-226 두 곳뿐입니다.
- **확인 창(모달)**: 되돌릴 수 없는 행동(확정, 라운드 완료, 세션 종료, 청백전 종료, 방식 변경, 팀 변경 후 재생성, 결과 수정, 거절, 역할 변경, 게스트 삭제, 비활성 처리)은 확인 창을 거칩니다. 확인 창은 화면(SCR)이 아니라 공통 컴포넌트로 04에서 정의합니다(UXD-006, UXD-010).
- **뒤로 가기**: 상세 화면(SCR-112, SCR-223, SCR-102)의 뒤로 가기는 목록·홈으로 돌아갑니다. 스테이지 플레이 중 '나가기'는 진행이 저장되지 않는다는 확인 창을 거칩니다(진행 기록은 스테이지를 마칠 때만 저장, C-23).
- **딥링크**: `/club-matches/:matchId`처럼 공유된 주소로 들어와도 같은 권한 규칙을 적용합니다. 미확정이거나 없는 청백전은 회원에게 존재 여부를 드러내지 않는 '찾을 수 없음' 상태로 보여 줍니다(AC-069).
- **이전 날짜 세션**: 오늘보다 이전 날짜의 미종료 세션은 별도 경로 없이 SCR-202 안에서 엽니다(UXD-076). 다시 들어오거나 새로고침하면 오늘 세션 화면과 이전 세션 배너로 돌아갑니다.
- **새로고침**: 실시간 갱신(WebSocket)은 범위 밖입니다. 화면을 열거나 새로고침할 때 최신 상태를 불러오고, 충돌은 처리 시점에 서버가 감지합니다(UXD-010, UXD-049).

## 6. 명명 규칙 (Figma 연동 대비)

UX 설계 문서, UI 프리뷰, 이후 Figma 파일이 같은 이름을 쓰도록 미리 정합니다. Figma 파일과 코드는 지금 만들지 않습니다.

### 6.1 화면 ID (`SCR-###`)
- 앞자리로 영역을 묶습니다. 번호는 재사용하지 않고, 폐기한 화면은 취소선으로 남깁니다.

| 대역 | 영역 |
|---|---|
| SCR-001–099 | 인증·공통 |
| SCR-101–109 | 회원 · 튜토리얼 |
| SCR-111–119 | 회원 · 청백전 |
| SCR-121–129 | 회원 · 마이페이지 |
| SCR-201–209 | 운영 · 홈과 실시간 대진 |
| SCR-211–219 | 운영 · 명단 |
| SCR-221–229 | 운영 · 청백전 관리 |
| SCR-231–239 | 운영 · 가입 승인·역할 |

- 화면 형태는 02의 `형태` 필드에 `독립 화면` | `시트`로 적습니다. r1의 `패널(모바일 시트·PC 옆 패널)`은 r2에서 `시트`로 통합했습니다(사용자 결정 D2). 확인 창과 안내 상자는 화면이 아니라 컴포넌트입니다.

### 6.2 상태 ID (`SCR-###-ST#`)
- 6종 표준 상태는 **고정 번호**를 씁니다. 해당하지 않으면 그 번호를 비워 두고 상태 표에 `해당 없음(사유)`으로 적습니다.

| 번호 | 상태 |
|---|---|
| ST1 | 기본 |
| ST2 | 로딩 |
| ST3 | 빈 상태 |
| ST4 | 오류 |
| ST5 | 권한 없음 |
| ST6 | 충돌 |
| ST7– | 화면 고유 상태(예: 대진 미확정, 종료, 미통과) |

- 어느 화면이든 `ST4`는 오류, `ST6`은 충돌이므로 Figma 프레임과 프리뷰 주소에서 같은 번호로 찾을 수 있습니다.

### 6.3 Figma·프리뷰 대응
| 대상 | 규칙 | 예 |
|---|---|---|
| Figma 페이지 | 화면 대역 이름 | `운영 · 청백전 관리` |
| Figma 프레임 | `SCR-### 화면 이름 / ST# 상태 / 플랫폼` | `SCR-223 청백전 운영 상세 / ST6 충돌 / mobile` |
| 프리뷰 주소 | `#SCR-###/SCR-###-ST#/플랫폼` | `#SCR-223/SCR-223-ST6/mobile` |
| 플랫폼 표기 | `mobile`(360–600px), `desktop`(≥1024px, 가운데 600px 열과 바깥 배경 확인용. 배치는 mobile과 같음) | |

### 6.4 컴포넌트 ID (`CMP-###`, 04에서 정의)
- `CMP-###` 번호와 영문 PascalCase 이름을 함께 씁니다. Figma 컴포넌트 이름은 `CMP-### 이름`, 변형은 Figma variant 속성으로 둡니다.
  - 예: `CMP-003 CourtCard`, variant `mode=review|live`, `team=numbered|blueWhite`
- 대역(예정): CMP-001–019 기본 요소(버튼, 칩, 배지, 입력), CMP-021–039 공통 패턴(시트, 확인 창, 목록 행, 안내 상자, 탭바), CMP-041– 도메인 컴포넌트(코트 카드, 경기 카드, 순위 카드, 튜토리얼 코트).

### 6.5 디자인 토큰 (04에서 값 정의)
- 이름은 `분류.역할.변형` 점 표기를 쓰고, CSS 변수는 같은 이름을 하이픈으로 바꿉니다. Figma Variables 컬렉션 이름은 분류와 같게 둡니다.

| 분류 | 예 | CSS 변수 |
|---|---|---|
| color | `color.bg.surface`, `color.text.primary`, `color.team.blue`, `color.team.white`, `color.status.warning` | `--color-team-blue` |
| space | `space.1`(4px) … `space.8` | `--space-4` |
| radius | `radius.sm`, `radius.md`, `radius.sheet` | `--radius-sheet` |
| font | `font.size.body`, `font.weight.bold` | `--font-size-body` |
| size | `size.touch.min`(44px), `size.content.member`(최대 열 너비, 값은 04에서 정의) | `--size-touch-min` |
| motion | `motion.duration.base`, `motion.tutorial.slow`(0.5배속) | `--motion-duration-base` |

- 팀·상태 색에는 반드시 글자·아이콘을 함께 씁니다(색만으로 구분하지 않음, 04에서 대비 확인).
