# UX 결정 기록 (UX Decisions): badminton-playbook

UX Planning 인터뷰에서 확정한 화면 기획 결정입니다. 질문과 답변 원문은 `.ai-workflow/design-notes.md`에 있습니다.
기준 기획: planning r3(승인됨, 2026-11-09 rebase. 이전 기준 r2). 기획에서 이미 확정된 사항(FR, NFR, 확정 사항 C-xx)은 다시 적지 않고 ID로만 참조합니다.

> **r3 rebase(2026-11-09)**: Discovery r3·Planning r3 기준으로 UXD를 정합성 복구했습니다. 기획 확정 사항을 반영한 문장은 '(r3 반영: …)', 기획과 맞지 않게 된 문장은 취소선, 대체·폐기된 UXD는 헤딩 취소선과 사유로 남겼습니다. 새로 정할 UI/UX는 라운드 20–22에서 질문합니다.

### UXD-001: 운영 화면은 휴대폰을 기준으로 설계한다
- **주제**: 실시간 대진
- **결정**: 운영진 화면은 휴대폰 한 손 조작을 기준으로 설계하고, PC에서는 같은 화면을 넓게 펼쳐(다단 배치) 반응형 요구를 충족합니다.
- **근거**: 권장안 수용(라운드 1, R01-Q1): 체육관에서 코트 사이를 오가며 참석, 생성, 라운드 완료를 처리하므로 휴대폰 사용이 가장 많습니다.
- **상태**: 권장안 수용
- **관련**: NFR-001, FLOW-004, US-008, US-010
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-002: 운동 세션은 대진 중심 한 화면으로 구성한다
- **주제**: 실시간 대진
- **결정**: 현재 라운드의 코트 카드와 주요 행동(대진 생성, 다시 생성, 확정, 라운드 완료)이 메인 화면입니다. 참석 체크와 대진 옵션은 버튼으로 여는 패널로 둡니다(모바일은 하단 시트, PC는 옆 패널). 첫 라운드를 생성하기 전에는 참석 패널이 자동으로 열립니다.
- **근거**: 권장안 수용(라운드 1, R01-Q2): 라운드마다 생성 → 확정 → 완료가 반복되고(FLOW-004-S4–S8), 참석은 라운드 사이에만 바뀌며, 옵션은 다음 라운드에도 유지됩니다(AC-023).
- **상태**: 권장안 수용
- **관련**: FLOW-004-S1, FLOW-004-S3, FLOW-004-S8, US-008, US-009, US-012, AC-023
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-003: 코트 카드는 이름·성별·점수·팀 점수 합을 보여 준다
- **주제**: 실시간 대진
- **결정**: 코트 카드는 두 팀을 나눠 보여 주고, 선수마다 이름, 성별, 1–10 점수를 표시하며, 팀별 점수 합도 보여 줍니다. 오늘 게임 수는 코트 카드에 넣지 않고 대기자 목록에서만 보여 줍니다. (r3 반영: C-24) 두 팀은 '1팀 / 2팀'으로 부르고, 카드에 '실력차 N점'(두 팀 1–10 점수 합 차이의 절댓값)을 함께 표시합니다. 4명 중 점수가 없는 사람이 있으면 '실력차 계산 불가'로 표시하고 0점으로 계산하지 않습니다. 확정 후에도 운영진 화면에는 계속 표시하며, 제한·경고 기준은 두지 않습니다.
- **근거**: 권장안 수용(라운드 1, R01-Q3): 다시 생성할지 판단하려면(FLOW-004-S5) 밸런스(C-02)와 혼복(C-03) 결과를 봐야 합니다. 운영진 전용 화면이라 점수 노출 규칙(FR-006, NFR-005)에도 맞습니다.
- **상태**: 권장안 수용
- **관련**: FLOW-004-S5, US-010, FR-006, NFR-005, C-02, C-03, AC-030, FR-022, US-022, AC-062, AC-063, C-24
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-004: 참석 체크는 이름순 목록 하나와 검색으로 한다
- **주제**: 실시간 대진
- **결정**: 참석 체크 목록은 이름순 목록 하나와 검색으로 구성합니다. 게스트는 목록 아래쪽에 '게스트'로 구분해 둡니다. 목록 위에는 참석 인원과 성별 분포를 고정해 보여 줍니다.
- **근거**: 권장안 수용(라운드 1, R01-Q4): 회원 18명 안팎을 체크하는 규모(AC-019)라 한 목록 스크롤과 검색이면 충분하고, 순서가 늘 같아야 빨리 찾습니다.
- **상태**: 권장안 수용
- **관련**: FLOW-004-S2, US-008, AC-019, AC-012
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-005: 대기자는 코트 카드 아래, 지난 라운드는 접어서 둔다
- **주제**: 실시간 대진
- **결정**: 메인 화면에서 코트 카드 아래에 대기자 섹션(이름, 성별, 오늘 게임 수)을 두고, 그 아래에 그날 지난 라운드 목록을 접힌 상태로 둡니다.
- **근거**: 권장안 수용(라운드 2, R02-Q1): 대기자는 다음 라운드에 우선 배정되므로(FR-009, C-04) 현재 라운드와 함께 봐야 하고, 지난 라운드는 가끔 확인하는 정보입니다.
- **상태**: 권장안 수용
- **관련**: FLOW-004-S4, FLOW-004-S7, FR-009, FR-012, US-010, US-012, AC-024, C-04
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-006: 확정·라운드 완료·세션 종료 전에는 확인 창을 띄운다
- **주제**: 실시간 대진
- **결정**: '확정', '라운드 완료', '세션 종료'를 누르면 짧은 한 줄 확인 창을 띄우고, 확인해야 처리합니다.
- **근거**: 권장안 수용(라운드 2, R02-Q2): 세 행동 모두 되돌릴 수 없고(AC-037, FR-012, FLOW-004-S9), 휴대폰 한 손 조작(UXD-001)에서는 잘못 누를 위험이 큽니다.
- **상태**: 권장안 수용
- **관련**: FLOW-004-S6, FLOW-004-S7, FLOW-004-S9, FR-011, FR-012, AC-037, AC-038
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-007: 규칙 완화는 상단 요약과 코트 카드 배지로 표시한다(Should)
- **주제**: 실시간 대진
- **결정**: 완화가 있으면 대진 위쪽에 한 줄 요약(예: '2경기에서 규칙 완화')을 두고, 해당 코트 카드에 완화된 규칙 배지(예: '성별 완화')를 붙입니다. 배지를 누르면 설명을 보여 줍니다. 완화가 없으면 아무것도 표시하지 않습니다.
- **근거**: 권장안 수용(라운드 2, R02-Q3): 휴대폰에서는 아래쪽 카드의 배지를 놓치기 쉽습니다.
- **상태**: 권장안 수용
- **관련**: FLOW-004-S4c, FR-013, US-013, AC-041, AC-061, C-03
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-008: 수동 교체는 선수를 누르고 하단 시트에서 고른다(Should)
- **주제**: 실시간 대진
- **결정**: 확정 전 대진에서 선수를 누르면 바꿀 수 있는 대상(대기자, 다른 경기 선수)이 하단 시트에 나오고, 하나를 고르면 맞바꿉니다. 확정한 뒤에는 교체 기능을 숨깁니다. (r3 반영: C-24) 교체 대상 목록에 대상마다 '교체 후 예상 실력차'를 보여 주고, 교체하면 코트 카드의 실력차를 즉시 다시 계산합니다.
- **근거**: 권장안 수용(라운드 2, R02-Q4): 한 손 조작(UXD-001)에서 드래그는 잘못 놓이기 쉽고, 참석·옵션 패널(UXD-002)과 같은 방식이라 익히기 쉽습니다.
- **상태**: 권장안 수용
- **관련**: FLOW-004-S5, FR-021, US-021, AC-035, AC-037, FR-022, AC-064, C-24
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-009: 수동 교체는 '같은 경기'만 막고, 다른 규칙 위반은 경고와 함께 허용한다(Should)
- **주제**: 실시간 대진
- **결정**: 교체 하단 시트에서 같은 날 같은 경기(같은 4명, 같은 팀 구성)가 되는 대상은 고를 수 없게 하고 사유를 보여 줍니다. 켜진 규칙(밸런스, 성별 조합, 중복 파트너 등)을 어기게 되는 교체는 허용하고, 해당 코트 카드에 완화 배지(UXD-007)와 같은 방식으로 경고를 표시합니다.
- **근거**: 권장안 수용(라운드 3, R03-Q1): 같은 경기는 항상 금지이고 0건이어야 하며(C-05, NFR-003), 나머지는 현장 사정으로 일부러 바꾸는 경우라 막으면 수동 교체의 목적(US-021)을 살리지 못합니다.
- **상태**: 권장안 수용
- **관련**: FR-021, US-021, AC-035, C-05, NFR-003, FR-013
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-010: 동시 조작 충돌은 확인 창으로 알리고 닫으면 최신 대진을 보여 준다
- **주제**: 실시간 대진
- **결정**: 확정할 때 충돌이 감지되면 "다른 운영진이 대진을 변경했습니다. 확정은 처리되지 않았습니다"라는 확인 창을 띄우고, 닫으면 최신 대진을 다시 보여 줍니다. 운영진은 최신 대진을 검토한 뒤 다시 확정합니다. (r3 반영: C-19) 청백전의 확정, 선수 교체, 결과 입력·수정, 방식 변경, 종료에서도 충돌이 감지되면 같은 방식의 확인 창으로 알리고 최신 상태를 보여 줍니다.
- **근거**: 권장안 수용(라운드 3, R03-Q2): 확정하려던 것과 다른 대진이 나타나므로 바뀐 사실을 확실히 인지해야 하고, 배너는 휴대폰 현장 사용에서 놓치기 쉽습니다.
- **상태**: 권장안 수용
- **관련**: FLOW-004-S6a, FR-011, US-011, AC-056, C-10, FR-015, FLOW-005-S6a, AC-080, C-19
- **영향 화면**: (UX 설계 단계에서 채움)

### ~~UXD-011~~: ~~전체 내비게이션은 역할에 따라 늘어나는 하단 탭바 하나로 한다~~ (r3에서 대체: UXD-066)

- **상태**: 권장안 수용
- **관련**: FR-003, AC-003, NFR-001, NFR-002, FLOW-001-S4, US-002
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-012: 가입 승인은 개별 처리와 선택 일괄 승인을 함께 둔다
- **주제**: 가입·로그인·승인·역할과 전체 내비게이션
- **결정**: 승인 목록(신청 순서)에서 신청자마다 '승인'·'거절' 버튼을 두고, 여러 명을 체크해 한꺼번에 승인할 수 있게 합니다. 거절은 일괄 처리하지 않고 한 명씩, 확인 창을 거쳐 처리합니다. (r3 반영: FR-004, FLOW-001-S2) 신청자마다 급수와 지인 정보(입력한 경우)를 함께 보여 줍니다.
- **근거**: 권장안 수용(라운드 4, R04-Q2): 서비스를 처음 열 때 기존 회원이 한꺼번에 신청하고, 평소에는 한두 명씩 신청합니다.

- **결정**: 대진 생성 전에는 팀 구성 패널에서 '청 / 백 / 불참'을 자유롭게 바꿉니다. 대진을 생성한 뒤 확정 전에 팀을 바꾸면 '팀을 바꾸면 대진을 다시 생성합니다' 확인 창을 띄우고, 확인하면 미확정 대진을 버리고 다시 생성합니다. 대진 확정 후에는 '청 / 백' 선택을 비활성화하고 이유('대진 확정 후에는 같은 팀 안에서 선수 교체만 할 수 있습니다')를 보여 주며, 선수 교체(UXD-043)만 허용합니다.
- **근거**: 권장안 수용(라운드 21, R21-Q1): 팀이 바뀌면 이미 만든 경기의 '청 2 대 백 2'(C-19)가 깨지므로 미확정 대진은 다시 만들고, 확정 후에는 기획대로 선수 교체만 허용합니다(C-15). 방식 변경 시 미확정 대진을 버리는 규칙(C-13, UXD-034)과 같은 원칙입니다. UXD-033을 대체합니다.
- **상태**: 권장안 수용
- **관련**: FR-014, FR-015, US-014, FLOW-005-S2, FLOW-005-S3c, C-13, C-15, C-19
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-071: 균등안은 총 경기 수 입력칸 바로 아래에 미리 계산해 제안한다
- **주제**: 청백전과 랭크
- **결정**: 총 경기 수를 입력하면 입력칸 바로 아래에 사람별 경기 수 분포를 바로 보여 줍니다(예: '14명 · 10경기 → 12명 3경기, 2명 2경기'). 모두 같은 경기 수가 되지 않으면 균등안 버튼(예: '7경기 · 모두 2경기', '14경기 · 모두 4경기')과 '입력값 유지' 버튼을 함께 둡니다. 균등안을 누르면 입력값이 바뀌고, 입력값을 유지하면 경기 수 차이는 최대 1이며 순위표에 사람별 경기 수를 표시합니다.
- **근거**: 권장안 수용(라운드 21, R21-Q2): 생성하기 전에 고를 수 있어 다시 생성할 일이 줄어듭니다(C-14, AC-074).
- **상태**: 권장안 수용
- **관련**: FR-015, US-015, FLOW-005-S3, FLOW-005-S3b, AC-074, C-14
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-072: 종료한 청백전은 상세 화면 맨 위에 최종 결과 카드를 둔다
- **주제**: 청백전과 랭크
- **결정**: 청백전을 종료하면 상세 화면 맨 위에 최종 결과 카드를 둡니다. 팀전은 '청팀 승리 (청 6 : 백 4)' 또는 '무승부 (5 : 5)', 개인전은 최종 순위(공동 순위 포함, 상위 3명 강조, 눌러서 전체 펼치기)를 보여 줍니다. 아래 경기 목록은 그대로 두어 종료 후 승패 수정(C-20)이 가능하고, 수정하면 카드가 다시 계산됩니다. 회원 청백전 화면(FR-024)에도 같은 카드를 보여 줍니다.
- **근거**: 권장안 수용(라운드 21, R21-Q3): 결과 기록 화면과 같은 자리에서 마무리가 보이고, 개인전 순위 요약 카드(UXD-037)를 이어 써서 새로 익힐 것이 없습니다.

### UXD-073: '튜토리얼 권장 · 미통과 N명'은 명단 위 필터 칩으로 둔다
- **주제**: 회원 명단·게스트·점수
- **결정**: 운영진의 명단 목록 위 필터 칩 줄에 '튜토리얼 권장 · 미통과 N명' 칩을 '점수 미설정 N명' 칩(UXD-025)과 나란히 둡니다. 0명이면 숨기고, 누르면 해당 회원만 보여 주며, 행을 누르면 편집 시트(UXD-022)에서 통과 현황을 봅니다. 칩은 운영진 화면에만 있고 회원에게는 보이지 않습니다.
- **근거**: 권장안 수용(라운드 21, R21-Q4): 권장 대상은 명단의 회원이고(FR-004), 이미 쓰는 필터 칩과 같은 방식이라 익히기 쉽습니다(C-23).
- **상태**: 권장안 수용
- **관련**: FR-026, FR-004, US-026, FLOW-003-S7, AC-097, C-23

### UXD-074: 명단은 회원(이름순) 위, 게스트 아래로 나누고 행에 이름·성별·급수·점수를 보여 준다
- **주제**: 회원 명단·게스트·점수
- **결정**: 명단 화면은 한 목록에 회원을 이름순으로 위에 두고, 게스트는 아래에 구분 머리글로 나눠 둡니다. 이름 검색을 둡니다. 각 행에는 이름, 성별, 급수, 점수를 보여 줍니다(예: '김민수 · 남 · C조 · 7점'). 급수가 없는 게스트는 급수 칸을 비웁니다. 급수 필터는 두지 않고, 랭크·전적·튜토리얼 현황은 목록에 표시하지 않습니다.
- **근거**: 권장안 수용(라운드 22, R22-Q1): 운영진이 점수를 매길 때 급수를 참고하므로 목록에서 함께 보이는 편이 빠릅니다(FR-004, C-21). 참석 체크 목록(UXD-004)과 같은 순서를 유지합니다. UXD-020을 대체합니다.
- **상태**: 권장안 수용
- **관련**: FR-004, US-005, US-006, FLOW-003-S1, AC-012, C-21
- **영향 화면**: (UX 설계 단계에서 채움)

### UXD-075: 청백전 목록은 방식·상태 배지와, 진행 중에는 요약, 종료 후에는 최종 결과를 보여 준다
- **주제**: 청백전과 랭크

### PF-002: 청백전을 개인전과 팀전 두 방식으로 운영
- **내용**: 청백전을 두 방식으로 구분합니다(2026-11-09 사용자 정정 요청).
  - **개인전**: 고정 팀(청·백)이 없습니다. 경기는 복식(2:2)이고 매 경기 파트너와 상대가 달라질 수 있습니다(경기별 임시 조). 이긴 조의 선수 2명에게 각각 개인 승수 +1을 주고, 개인별 누적 승수로 순위를 매깁니다. 예: 1경기 철수·영희 승 → 각 1승, 2경기 철수·민수 승 → 철수 2승, 민수 1승.
  - **팀전**: 참가자를 청팀과 백팀으로 나눕니다. 경기는 복식(2:2)으로 청팀 선수 대 백팀 선수입니다. 이긴 쪽 소속 팀에 팀 승수 +1을 주고, 청·백 누적 팀 승수로 최종 승리 팀을 정합니다. 최종 순위 기준은 개인 승수가 아니라 팀 승수입니다.
  - **차이**: 개인전은 고정 팀이 없고 결과가 '개인 승수·개인 순위'로 집계됩니다. 팀전은 고정 팀이 있고 결과가 '팀 승수·최종 승리 팀'으로 집계됩니다.
- **이유(현재 기획과 충돌·누락)**:
  - FR-014, US-014, FLOW-005-S2, FLOW-005-S2a, AC-042: 모든 청백전에서 참가자를 청팀·백팀으로 나누고 팀별 인원을 보여 준다고 정함 → 개인전(고정 팀 없음)과 충돌. 청백전 생성 시 방식 선택이 없음(FLOW-005-S1 누락)
  - FR-015, US-015, FLOW-005-S3, FLOW-005-S3a, AC-043: 경기는 '청팀 2명 대 백팀 2명'만 허용 → 개인전(참가자 4명을 임시 조 2개로)과 충돌
  - FR-015, FLOW-005-S4, FLOW-005-S4a, AC-044, AC-057: 결과는 '이긴 팀(청/백)'을 기록 → 개인전은 '이긴 조(선수 2명)'를 기록해야 함
  - FR-016, US-016, C-07, AC-045, AC-046, AC-047: 랭크는 회원의 청백전 승패를 전체 누적한 **승률**로 S/A/B/C를 매김 → 개인전의 '청백전별 개인 누적 승수 순위', 팀전의 '팀 승수로 최종 승리 팀'이라는 집계 기준이 기획에 없음. 두 집계와 기존 랭크의 관계도 정해지지 않음
  - FR-019, AC-053: 마이페이지 전적(경기 수, 승, 패, 승률)이 방식 구분 없이 정의됨
  - C-09, AC-057: 게스트 참가와 '회원의 승패만 랭크에 반영'이 팀 승패 기준으로만 정의됨 → 개인전 순위에서 게스트를 어떻게 다룰지 없음
  - PRD 6장 범위 제외 '전체 랭킹 보드': 개인전의 청백전별 개인 순위 표시와의 경계를 정해야 함
  - 기획 배경(01-discovery의 청백전·랭크 설명, PRB-004·GOAL-003)도 '청·백 팀 편성'만 전제
- **변경이 필요한 규칙(기획 재검토에서 정할 것)**:
  - 경기 생성: 청백전을 만들 때 방식(개인전/팀전)을 고름. 개인전은 참가자 목록에서 경기마다 4명을 2명씩 두 조로 편성(검사: 4명 모두 다른 사람). 팀전은 기존처럼 청 2 대 백 2
  - 결과 입력: 개인전은 이긴 조(선수 2명)를 기록, 팀전은 이긴 팀(청/백)을 기록. 둘 다 수정 가능(기존 FR-015 유지 여부 확인)
  - 집계: 개인전은 선수별 누적 승수와 순위, 팀전은 청·백 누적 팀 승수와 최종 승리 팀
- **미결정 사항(기획 수준, 임의로 정하지 않음)**:
  - 개인전 순위의 동률 처리, 팀전 팀 승수 동률(무승부) 처리
  - 개인전 순위 기준이 '승수'만인지(출전 경기 수가 다를 때의 공정성), 패 기록 여부
  - 승점 가중치 여부
  - 개인전 경기 편성 방식(운영진 수동 편성만인지, 실시간 대진 알고리즘을 쓰는지)
  - 방식을 생성 후 바꿀 수 있는지
  - 두 방식의 결과가 기존 랭크(FR-016, S/A/B/C)에 반영되는지, 반영된다면 어떻게(팀전에서 개인의 승패를 계산하는지)
  - 게스트의 개인전 순위 포함 여부, 팀전 팀 승수 기여 여부(C-09 확장)
  - 청백전의 '종료·최종 결과 확정' 상태가 필요한지(팀전 최종 승리 팀 결정 시점)

### PF-003: 결과 기록 전 청백전 경기 삭제
- **내용**: 편성을 잘못한 청백전 경기를, 승패를 기록하기 전에 한해 삭제할 수 있게 하고 싶다(라운드 11, R11-Q3 사용자 선택)
- **이유**: FR-015는 경기 편성과 승패 기록·수정만 정하고 경기 삭제는 정하지 않았습니다. 삭제 기능을 더하려면 FR-015와 관련 AC(AC-043, AC-044)를 바꾸거나 새 AC를 추가해야 하므로 기획 재검토 대상입니다. 삭제가 없으면 잘못 만든 경기가 '미기록 경기 수'(UXD-028)에 계속 남습니다.
- **처리 시점**: 모든 주제 인터뷰가 끝난 뒤 다른 PF와 함께 /product-start 기획 재검토. 재승인 전까지 디자인은 현재 기획(경기 삭제 없음) 기준
- **상태**: 해결(종결)
- **관련**: FR-015, US-015, AC-043, AC-044, FLOW-005-S3
- **해결 내용**: 기획 변경 불필요. 청백전은 확정 전·후 모두 개별 경기 추가·삭제를 하지 않고, 경기 수는 총 경기 수를 고쳐 다시 생성으로 조정(C-14, 정책 확인 6차)

### PF-004: 운영진 명단 편집 시트에 회원 랭크·청백전 전적 표시

- **처리 시점**: 모든 주제 인터뷰가 끝난 뒤 다른 PF와 함께 /product-start 기획 재검토. 재승인 전까지 디자인은 현재 기획(운영진 화면에 랭크 없음) 기준
- **상태**: 해결(기획 반영 r3)
- **관련**: FR-016, FR-019, FR-004, US-016, US-019, AC-045, AC-053
- **해결 내용**: Planning r3 FR-004에 반영(회원 편집 화면의 랭크·누적 청백전 전적, 회원만, 목록 미표시, AC-100). 정책 확인 6차

### PF-005: 로테이션 학습을 게임형 로테이션 튜토리얼로 전환
