# 화면 목록과 화면별 명세 (Screens): 배드민턴 플레이북 (badminton-playbook)

> 구조 확인(checkpoint r1, 2026-11-09) 뒤 상세를 채운 문서입니다. (r4, 2026-11-10) Planning r4(C-25, C-26, AC-101–AC-107)와 UX Planning r2(UXD-076, UXD-006·UXD-022 r4 정합성)에 맞춰 SCR-202, SCR-212, SCR-224, SCR-102, SCR-103, SCR-005를 부분 수정했습니다. 화면 구성·라우트는 바뀌지 않았습니다. 화면마다 최소 필드, 레이아웃(모바일·PC 차이), 정보 우선순위와 권한별 노출, 행동, 입력·검증, 상태 표(6종 + 고유 상태), 시트·패널 동작, 컴포넌트를 둡니다.
> 상태 번호는 `01` 6.2의 고정 번호(ST1 기본, ST2 로딩, ST3 빈 상태, ST4 오류, ST5 권한 없음, ST6 충돌, ST7– 고유 상태)를 따릅니다.

```
[운영]     SCR-201 ─┬→ SCR-202 ─┬→ SCR-203 ─┬→ SCR-213
                    │           │           └→ SCR-214
                    │           ├→ SCR-204
                    │           └→ SCR-205
                    ├→ SCR-211 ─┬→ SCR-212
                    │           └→ SCR-213
                    ├→ SCR-221 ─┬→ SCR-222 ─만들기→ SCR-223
                    │           └→ SCR-223 ─┬→ SCR-224 ─┬→ SCR-214
                    │                       │           └→ SCR-226
```

## 화면별 명세

> 공통 규칙(화면마다 반복하지 않음)
> - 상태 번호: ST1 기본, ST2 로딩, ST3 빈 상태, ST4 오류, ST5 권한 없음, ST6 충돌, ST7– 고유 상태(`01` 6.2).
> - 로딩: 처음 불러올 때는 내용 자리에 스켈레톤(CMP-027), 버튼 행동 중에는 그 버튼만 진행 표시와 비활성(중복 제출 방지, CMP-001).
> - 오류: 불러오기 실패는 화면 블록 오류(CMP-027, '다시 시도'), 저장 실패는 시트·화면 위쪽 안내 상자(CMP-023)로 원인과 다음 행동을 알리고 입력값은 유지합니다. 네트워크 실패(`network_error`)는 "연결이 불안정합니다. 다시 시도해 주세요"로 통일합니다.
> - 권한 없음: 독립 화면은 `01` 5장의 리다이렉트를 따르고, 시트·패널은 부모 화면에서 처리합니다.
> - 확인 창(CMP-022), 저장 완료 토스트(CMP-029)는 `04` 3장의 공통 패턴을 따릅니다.
> - 회원 화면(SCR-0xx·1xx)은 PC에서도 최대 480px 한 열(NFR-002, AC-050). 운영 화면(SCR-2xx)의 PC(≥1024px) 배치는 화면마다 '반응형' 항목에 적습니다.


### 저장 규칙(멱등)
- 저장 단위는 회원 × 스테이지 기록 한 건이며, 서버는 한 번의 원자적 갱신으로 처리합니다. 시도마다 기록을 늘리지 않습니다(C-23).
- 통과 여부: 기존 값 OR 이번 값(한 번 통과하면 계속 통과). 최고 점수: 기존 값과 이번 값 중 큰 값(AC-094). 최초 통과 시각: 비어 있고 이번에 통과했을 때만, 서버에 통과 기록이 처음 성공적으로 저장된 시각으로 기록하고 이후 바꾸지 않습니다.
- 그래서 같은 결과를 여러 번 보내도(재시도, 응답 시간 초과 후 재전송, 두 기기 동시 저장) 결과가 같습니다. 클라이언트는 저장 중 '다시 저장'을 비활성화해 동시 요청을 줄입니다.

### 상태 전이(세션·라운드)
```
ST3 오늘 세션 없음 ─'오늘 운동 시작'→ ST1 생성 전(첫 라운드면 참석 패널 자동 열림)

                              └→ ST4 오류(4명 미만 · 점수 미설정 · 생성 실패) → ST1
ST7 ─'다시 생성'→ ST2 → ST7 (새 시드, 세션 이력 그대로, AC-036)
ST7 ─선수 누르기→ SCR-205 교체 → ST7
ST7 ─참석·옵션 변경→ 대진은 그대로 두고 "참석·옵션이 바뀌었습니다. 다시 생성하면 반영됩니다" 안내
ST7 ─'확정'·확인 창→ ST8 라운드 진행 중 / 충돌이면 ST6 → 닫기 → 최신 상태(ST7 또는 ST8)
ST8 ─'라운드 완료'·확인 창→ ST1 다음 라운드 생성 전(지난 라운드에 쌓임, 대기자 우선)

```
- ST8에서는 '대진 생성'을 표시하지 않고, 대신 "현재 라운드를 먼저 완료하세요" 안내를 생성 버튼 자리에 둡니다(AC-039).
- (r4, C-25) ST8에서는 '세션 종료'를 비활성화하고 "진행 중인 라운드를 먼저 완료하세요"를 보여 줍니다. 서버도 거부합니다(AC-101).
- (r4, C-25) 세션 종료 확인 창 문구: "오늘 세션을 종료할까요? 종료한 세션은 복구할 수 없고, 오늘은 새 세션을 만들 수 없습니다." 확정 전 대진이 있으면 "확정하지 않은 대진은 폐기됩니다"를 한 줄 더합니다(AC-102, AC-104, UXD-006).
- (r4, C-25) 세션 날짜는 생성 시점의 KST 날짜이며 자정이 지나도 바뀌지 않습니다. 오늘 세션이 이미 있으면 '오늘 운동 시작' 대신 그 세션이 열립니다(AC-103). 이미 열어 둔 화면은 자정이 지나도 다른 세션으로 바뀌지 않습니다(UXD-076).
- (r4, UXD-076) 이전 날짜 세션을 '이어서 열기'로 열면 같은 화면에서 그 세션을 보여 주고, 헤더 제목 옆에 '11/02(일) 세션' 날짜 배지와 '오늘 세션으로' 링크를 둡니다. 그 세션에서 진행한 경기와 결과는 그 세션에 기록되며, 오늘 세션의 참석자·대진·이력과 섞이지 않습니다(C-25).
- (후속 검토) 이전 날짜 미종료 세션이 여러 개일 때의 배너 처리는 기획에 정의되어 있지 않아 정하지 않았습니다(UXD-076 후속 검토). 이 명세는 하나인 경우만 다룹니다.
