# 디자인 방향 (Design Direction): 배드민턴 플레이북 (badminton-playbook)

승인된 UX 설계를 바꾸지 않고, 그 위에 어떤 모습으로 렌더링할지 정합니다. 여기서 승인된 시각 결정(VD)만 정식 렌더링(프리뷰)에 씁니다.
화면·정보·행동·토큰 이름을 바꿔야 하면 이 문서에서 결정하지 않고 7장 변경 요청(①·②)으로 남겨 UX 설계를 다시 엽니다.

> 결정 기록(2026-11-11, 사용자): UX Spec r1 유지(r2 개정 보류). C안 테마 값(청록·Pretendard)은 테마 파일로 적용. UX Spec의 정보 구조·행동을 바꾸는 C안 요소는 현재 적용하지 않음. 렌더러 code. VD-003·004·008·010·020 확정, CR-004·005·006 거절, CR-007 시각 표현으로 반영, CR-010 `radius.md` 적용.

### '적용 거절'과 '향후 재검토 후보'의 구분

엔진의 변경 요청 상태는 `미결`·`반영`·`기각`·`UX Spec 개정 요청` 네 가지뿐이고 '보류'가 없습니다. 그래서 CR-001–003은 상태를 `기각`으로 적되, 의미를 둘로 나눕니다.

| 관점 | CR-001–003 | CR-004–006 |
|---|---|---|
| 현재(UX Spec r1, 이 Design Direction) | **적용 거절**: 정식 렌더는 승인 명세대로 | **적용 거절** |
| 향후 UX Spec r2 개정 | **재검토 후보**: r2를 열 때 이 목록에서 다시 꺼냄(실험 근거: `experiments/c-preview-poc/`, `docs/design-profile/reviews/`) | 재검토 예정 없음(현재 UX Spec 기준으로 결정 종료) |

- 엔진 상태 `UX Spec 개정 요청`을 쓰지 않은 이유: 그 상태는 '지금 UX 설계를 다시 연다'는 뜻이라 Design Direction 제출이 막힙니다. 사용자는 r2 개정을 보류했습니다.

- **브랜드·시각 방향**: C안 Mint Hybrid의 테마 값(청록 주 행동 색·포커스 링, Pretendard)만 적용하고, 화면 구조는 승인된 UX 설계 그대로. 테마 값은 `docs/design-profile/theme.json`(개발자 설정)
- **컴포넌트·토큰 매핑**: `docs/design-profile/component-mapping.md`(CMP ↔ shadcn/ui + Radix), `docs/design-profile/token-mapping.md`(04 토큰 → CSS 변수)

## 2. 디자인 방향과 스타일 원칙

- 체육관 현장에서 한 손으로 빨리 읽고 누르는 업무 화면: 정보 밀도는 높게, 카드·그라데이션·장식은 쓰지 않음
- 브랜드 색(청록)은 04의 `color.action.primary`·`color.focus.ring` 의미 그대로(주 버튼, 링크, 선택 상태, 포커스)에만 씀. 상태 색과 팀·코트 색은 04 값 그대로
- 화면 구조·정보·행동은 승인된 02 그대로(헤더 → 안내 줄 → 검색 → 칩 → 목록, '게스트 추가'는 모바일 오른쪽 아래)
- 모든 누름 대상은 누름 영역 44 이상. 보이는 크기와 누름 영역을 따로 정함. 글자 대비 4.5:1(큰 글자 3:1), 색만으로 구분하지 않음
