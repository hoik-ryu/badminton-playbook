# UI 컴포넌트와 디자인 토큰 (UI System): 배드민턴 플레이북 (badminton-playbook)

`02-screens.md`에서 **실제로 반복해 쓰인 것만** 컴포넌트로 정의합니다. 특정 디자인 시스템이나 도구에 묶이지 않으며(CLAUDE.md), 이름은 `01` 6장의 명명 규칙을 따라 Figma Variables·컴포넌트와 CSS 변수에 그대로 옮길 수 있게 둡니다.
값은 시각 디자인 단계(UI Preview)에서 바뀔 수 있는 초기값입니다. 토큰 값 변경은 UX 설계 변경으로 처리합니다(`reference/preview.md`).

> **r2 개정(2026-11-13)**: 기획 r6(NFR-001·NFR-002·AC-050)과 UX 결정 r4(사용자 결정 D1–D6), 청백전 운영 정책(Planning r5)을 반영했습니다. 변경안: `docs/workflow-proposals/ux-spec-r2-change-plan.md` X8·X9·X14, Y6–Y8·Y10.
> - 토큰(1.3·1.5): `size.content.member` 480px → 600px(이름 유지). PC 전용 토큰 3개(`size.panel.side`, `size.nav.side`, `size.content.ops.max`)는 **삭제하지 않고 미사용**으로 표시(D5). 1.5를 PC·모바일 공통 한 열로 다시 씀
> - 컴포넌트: CMP-021 Sheet `presentation=bottom`만(side·dialog 없음), CMP-025 AppNav `layout=bottom`만(side 없음), CMP-005·CMP-023·CMP-041에 r5 상태 추가. 컴포넌트 ID·번호는 그대로
> - 3장 공통 패턴: 한 열 원칙, 페이지 좌우 여백, 섹션 간격, 제목 계층, 카드와 Flat 구분(D4·D6), 하단 고정 요소·안전 영역, 하단 시트 규칙(Y10) 추가. 기존 패턴(확인 창·토스트·빈 상태·오류·충돌·로딩·권한·팀 표기)은 그대로
> - 새 토큰·새 컴포넌트·새 변형 값은 만들지 않았습니다. 구체적인 시각 값(여백·간격 단계, 카드 표현)은 Design Direction r2에서 기존 토큰 중에서 고릅니다(D6).

- (r2) 기준점은 배치를 바꾸지 않습니다. 모든 폭에서 같은 한 열·하단 탭·하단 시트를 쓰고, 열 너비만 600px까지 늘어납니다(NFR-001, NFR-002, AC-050, 사용자 결정 D1·D2). 기준점 토큰은 열 바깥 배경 표시와 프리뷰 프레임(`01` 6.3) 구분에만 씁니다.

- 설계 기준 폭은 360px(가장 좁은 폭)과 390px이며, 200% 확대에서도 가로 스크롤이 생기지 않게 합니다(WCAG 1.4.10).
- 어떤 화면도 어떤 폭에서 600px 열을 넘지 않습니다. 열 바깥에는 콘텐츠·메뉴·버튼을 두지 않습니다.

## 2. 컴포넌트

번호 대역: CMP-001–019 기본 요소, CMP-021–039 공통 패턴, CMP-041– 도메인 컴포넌트(`01` 6.4). Figma 컴포넌트 이름은 `CMP-### 영문이름`, 변형은 variant 속성으로 둡니다.

### CMP-001: Button
- **용도**: 화면·시트의 행동(가입 신청, 대진 생성, 확정, 저장, 승인 등)
- **변형**: `variant=primary|secondary|danger|text|kakao`, `size=md(44px)|lg(48px)`, `fullWidth`
- **상태**: 기본, 눌림, 비활성(사유 문구를 근처에 표시), 로딩(진행 표시·중복 제출 막기)
- **사용 화면**: SCR-001, SCR-002, SCR-003, SCR-004, SCR-005, SCR-102, SCR-103, SCR-121, SCR-122, SCR-202, SCR-203, SCR-211, SCR-212, SCR-213, SCR-221, SCR-222, SCR-223, SCR-226, SCR-231, SCR-232
- **접근성**: 버튼 글자가 곧 레이블, 비활성 사유는 `aria-describedby`, 포커스 링 color.focus.ring

### CMP-002: SegmentedControl
- **용도**: 2–3개 중 하나 고르기(남·여, 개인전·팀전, 레벨별·무작위, 청·백·불참)
- **변형**: `options=2|3`, `size=md|sm`(목록 행 안은 sm, 최소 44px 유지)
- **상태**: 기본, 선택됨(색 + 굵은 글자 + 체크), 비활성(잠금 사유 표시)
- **사용 화면**: SCR-002, SCR-122, SCR-204, SCR-212, SCR-213, SCR-222, SCR-223, SCR-224
- **접근성**: `role="radiogroup"`, 방향키 이동

### CMP-003: ChoiceGrid
- **용도**: 여러 값 중 하나를 버튼 격자로 고르기(급수 8개 4×2, 점수 1–10 5×2)
- **변형**: `kind=grade(4열)|score(5열)`, `allowClear`(점수 미설정으로 되돌리기)
- **상태**: 기본, 선택됨, 오류(그리드 아래 오류 문구), 저장 중(누른 칸만)
- **사용 화면**: SCR-002, SCR-122, SCR-212, SCR-213, SCR-214
- **접근성**: `role="radiogroup"` + 그룹 레이블('급수', '점수'), 칸 최소 44×44px

### CMP-004: FilterChip
- **용도**: 목록 필터('점수 미설정 N명', '튜토리얼 권장 · 미통과 N명')
- **변형**: `count`(0이면 숨김)
- **상태**: 기본, 켜짐, 숨김
- **사용 화면**: SCR-211
- **접근성**: `aria-pressed`, 숫자를 포함한 레이블

### CMP-005: Badge
- **용도**: 짧은 상태·구분 표시(방식, 청백전 상태, 팀, 미설정, 게스트, 비활성, 변경됨, 귀가, 출전, 규칙 완화, 역할, 대기 건수). (r2, X8) '결과 수정됨'(종료 후 결과가 바뀐 경기, SCR-223-ST9·SCR-112-ST8, AC-110), '같은 대진 반복'(청백전 완화, 사유를 붙여 '같은 대진 반복 · {사유}', AC-108, UXD-007)
- **변형**: `tone=neutral|info|warning|danger|success|teamBlue|teamWhite`, `shape=label|count`
- **상태**: 기본(정적)
- **사용 화면**: SCR-111, SCR-112, SCR-201, SCR-202, SCR-205, SCR-211, SCR-212, SCR-221, SCR-223, SCR-224, SCR-225, SCR-232
- **접근성**: 항상 글자 포함(색만으로 구분하지 않음, WCAG 1.4.1). 누를 수 있는 배지(규칙 완화)는 버튼 역할

### CMP-006: TextField
- **용도**: 한 줄 입력(이름, 지인, 날짜, 총 경기 수), 이름 검색
- **변형**: `type=text|search|date|number`
- **상태**: 기본, 포커스, 오류(아래 오류 문구), 비활성
- **사용 화면**: SCR-002, SCR-122, SCR-203, SCR-211, SCR-212, SCR-213, SCR-222, SCR-223, SCR-224, SCR-232
- **접근성**: 보이는 레이블, 오류 `aria-invalid` + `aria-describedby`, 글자 16px(모바일 확대 방지)

### CMP-007: Switch
- **용도**: 켜기/끄기(대진 규칙, 청백전 규칙, '비활성 포함')
- **변형**: `withDescription`(한 줄 설명)
- **상태**: 켜짐, 꺼짐, 비활성
- **사용 화면**: SCR-204, SCR-211, SCR-223
- **접근성**: `role="switch"`, 레이블 + 상태 읽기

### CMP-008: Checkbox
- **용도**: 여러 사람 고르기(참석, 개인전 참가, 일괄 승인)
- **변형**: `rowMode`(행 전체가 누름 영역), `selectAll`
- **상태**: 선택, 해제, 비활성(사유 표시)
- **사용 화면**: SCR-203, SCR-224, SCR-231
- **접근성**: 체크 아이콘 + 행 레이블, 행 높이 48px

### CMP-021: Sheet
- **용도**: 부모 화면 위에 여는 하단 시트(SCR-122, SCR-203–205, SCR-212–214, SCR-222, SCR-224–226, 랭크 기준 안내)
- **변형**: `presentation=bottom`(PC·모바일 공통, 600px 열 아래쪽에서 열림), `height=content|70%|full`, `stacked`(시트 위 두 번째 시트). (r2) r1의 `side`(PC 옆 패널)·`dialog`(PC 가운데 대화상자)는 없앴습니다(사용자 결정 D2, UXD-002·022·038)
- **상태**: 열림, 닫힘, 입력 중 닫기 확인(CMP-022), 저장 중(저장 버튼 로딩), 저장 실패(시트 위쪽 안내 상자, 입력값 유지). 열기·닫기·중첩 규칙은 3장 '하단 시트 규칙'

## 3. 공통 패턴

- **확인 창(CMP-022)**: 되돌릴 수 없는 행동(확정, 라운드 완료, 세션 종료, 청백전 종료, 방식 변경, 팀 변경 후 재생성, 결과 반대로 수정, 거절, 역할 변경, 게스트 삭제, 비활성 처리)과 입력 중 닫기, 스테이지 나가기에만 씁니다. 처음 결과 기록·참석 체크·옵션 변경·다시 생성은 확인 없이 바로 반영합니다. 제목은 질문형, 본문은 결과 한 줄, 행동 버튼은 동사입니다.
- **토스트(CMP-029)**: 성공 알림만 3초. 실패는 토스트로 알리지 않고 안내 상자(CMP-023)로 화면에 남깁니다.
- **빈 상태(CMP-027 empty)**: 왜 비었는지 + 할 수 있는 다음 행동 버튼 하나. 검색·필터 결과 없음은 조건 해제 버튼.
- **오류 표시**: 입력 오류는 필드 아래(CMP-006·CMP-003), 저장 실패는 시트·화면 위쪽 안내 상자(CMP-023, 입력값 유지), 불러오기 실패는 블록 오류(CMP-027, '다시 시도'). 문구는 원인 + 해결 방법. 네트워크 실패는 "연결이 불안정합니다. 다시 시도해 주세요".
- **충돌 안내**: 기획이 정한 지점(SCR-202 확정, SCR-223·SCR-225·SCR-226의 청백전 조작; FLOW-004-S6a, FLOW-005-S6a)에서만 충돌 확인 창(CMP-022 `tone=conflict`) "다른 운영진이 …을 변경했습니다. 방금 한 작업은 처리되지 않았습니다" → '확인' → 최신 상태를 다시 불러옴. 그 밖의 화면에서 이미 처리된 요청은 오류 안내 상자로 알리고 목록을 새로고침합니다.
- **로딩**: 처음 불러오기는 스켈레톤, 행동 중에는 누른 버튼만 진행 표시하고 같은 행동을 막습니다(중복 제출 방지). 대진 생성은 2초 안(AC-034), 스테이지 준비는 3초 안(AC-095)을 목표로 하며 넘으면 문구를 유지합니다.
- **권한별 노출**: 회원 화면 컴포넌트(`audience=member`)는 1–10 점수·팀 점수 합·실력차·다른 회원의 급수·지인·튜토리얼 진행·랭크를 그리지 않습니다(NFR-005, AC-066, AC-068). 화면에서 숨기는 것과 별개로 API 응답에도 없어야 합니다(구현 단계 계약 테스트).
- **팀 표기**: 팀전은 '청팀 / 백팀'(색 띠 + 글자, 백팀은 테두리형), 개인전과 실시간 대진은 '1팀 / 2팀'(글자만, C-24).

### 3.1 레이아웃 공통 패턴 (r2, 사용자 결정 D1·D4·D6)

아래는 구조와 역할만 정합니다. 어떤 토큰 단계를 쓸지(구체적인 값)는 Design Direction r2에서 기존 토큰 중에서 고르고, 새 값은 만들지 않습니다(D6).

- **한 열 원칙**: 모든 화면은 가운데 정렬한 한 열(최대 `size.content.member` 600px)에 위에서 아래로 쌓습니다(1.5). 콘텐츠 블록을 좌우로 나란히 두는 다단 배치는 쓰지 않습니다. 한 블록 안의 작은 격자(ChoiceGrid 4×2·5×2, 나란한 두 버튼, 청·백 결과 버튼)는 한 열 안의 요소라 허용합니다. 열 바깥에는 배경만 둡니다.
- **페이지 좌우 여백**: 열 안쪽 좌우 여백은 모든 화면에서 같은 값을 쓰고, 화면 제목(CMP-026)·목록·카드·하단 고정 바·시트 내용의 왼쪽 시작선을 맞춥니다. 기본은 `space.gutter.mobile`이며, 열이 600px에 닿는 넓은 화면에서 `space.gutter.desktop`으로 넓힐지는 Design Direction에서 정합니다. 목록 행(CMP-024·CMP-030)은 누름 영역을 열 끝까지 넓히되 글자는 같은 시작선에 둡니다.
- **섹션 간격**: 간격은 세 단계 역할로 나눕니다. ① 섹션 사이(예: SCR-121의 랭크·전적·프로필, SCR-223의 요약·대진 설정·경기 목록) ② 섹션 안 항목 사이(카드와 카드, 입력칸과 입력칸) ③ 한 요소 안(제목과 보조 글, 아이콘과 글자). 항상 ① > ② > ③이고, 각 단계는 `space.*` 중 하나로 화면 전체에서 통일합니다(값은 Design Direction).
- **제목 계층**: 1.3 글자 토큰의 용도를 제목 단계에 대응시킵니다. 한 화면에 `h1`은 하나(CMP-026 화면 제목, `font.size.heading`). 섹션 머리·시트 제목·카드 제목은 `h2`(`font.size.title`, `font.weight.bold`), 섹션·시트·카드 안의 작은 묶음 머리(예: '── 게스트 ──', '── 현황 ──')는 `h3`(`font.size.body`, `font.weight.bold`). 본문은 `font.size.body`, 보조 정보는 `color.text.secondary`로 구분하며 `font.size.caption`은 1.3의 '보조' 용도(배지·시각·단위 등 짧은 글자)에 씁니다. 큰 숫자 강조(결과 점수·랭크 등급)만 `font.size.display`. 제목 단계를 건너뛰지 않습니다(WCAG 1.3.1). 굵기·크기 외의 시각 처리(색·간격)는 Design Direction에서 정합니다.
- **카드와 Flat 구분(D4)**: 카드는 일괄 금지가 아니라 목적이 있을 때만 씁니다.
  - **카드를 쓰는 경우**: 한 덩어리로 읽고 비교하거나 그 단위로 행동하는 정보 묶음. 경기·코트(CMP-041), 결과·순위 요약(CMP-042), 청백전 목록 항목(CMP-043), 랭크·전적 요약(CMP-045), 스테이지(CMP-047), 내 다음 경기 강조(UXD-049).
  - **Flat(카드 없이 행·구분선·섹션 머리로 구분)**: 같은 형식이 반복되는 목록(사람 행 CMP-024, 메뉴·남은 경기 CMP-030, 후보 CMP-044), 입력·설정 묶음(폼, 스위치·옵션), 필터·검색 영역, 한 줄 안내(NoticeBox CMP-023는 자체 배경만).
  - 카드 안에 카드를 두지 않습니다(한 단계만). 시트는 이미 표면이므로 시트 안 내용은 원칙적으로 Flat이며, 시트 안에서도 위 '카드를 쓰는 경우'에 해당하는 묶음만 카드로 둡니다.
  - 카드 표현(테두리 `color.border.default`·그림자 `elevation.card`·모서리 `radius.md` 중 무엇을 쓸지)은 Design Direction에서 정합니다.
- **하단 고정 요소와 안전 영역**: 하단 탭바(CMP-025), 화면의 하단 고정 행동 바, 오른쪽 아래 주 버튼(SCR-211 '게스트 추가', UXD-026·D3)은 모두 600px 열 안에 둡니다.
  - 쌓는 순서(아래에서 위로): 기기 안전 영역(`env(safe-area-inset-bottom)`) → 하단 탭바 → 하단 고정 행동 바 또는 오른쪽 아래 주 버튼. 서로 겹치지 않습니다. 탭바를 숨기는 화면(SCR-102, SCR-103)은 안전 영역 바로 위에 둡니다.
  - 고정 요소가 있는 화면은 스크롤 내용 끝에 고정 요소 높이만큼 여백을 두어 마지막 행·카드가 가리지 않게 합니다.
  - 고정 요소와 열 가장자리 사이 간격은 '페이지 좌우 여백'과 같은 값을 씁니다.

### 3.2 하단 시트 규칙 (r2, 사용자 결정 D2, 변경안 Y10)

CMP-021을 쓰는 모든 시트에 적용합니다. 시트 위 시트는 `01` 5장의 두 곳(SCR-203 → SCR-213·SCR-214, SCR-224 → SCR-214·SCR-226)뿐입니다.

- **닫기 순서**: ✕ 버튼, 바깥(딤) 누르기, Esc, 브라우저 뒤로 가기는 모두 **맨 위 시트 하나만** 닫습니다. 두 번째 시트를 닫으면 첫 번째 시트로, 첫 번째 시트를 닫으면 부모 화면으로 돌아갑니다. 한 번에 여러 시트를 닫지 않습니다.
- **아래 상태 보존**: 위 시트를 닫으면 아래 시트의 입력값·스크롤 위치·검색어·필터·체크 상태를 그대로 둡니다. 부모 화면(SCR-202, SCR-211, SCR-223 등)도 시트를 닫은 뒤 필터·검색어·스크롤 위치와 접힘 상태를 유지합니다.
- **포커스 복원**: 시트를 닫으면 그 시트를 연 요소로 포커스를 돌려줍니다(두 번째 시트를 닫으면 첫 번째 시트 안의 그 버튼). 연 요소가 사라졌으면(예: 행이 삭제됨) 그 목록의 제목이나 다음 행으로 보냅니다.
- **저장**: 저장에 성공하면 **그 시트만** 닫고 아래 시트·부모 화면의 해당 값을 갱신합니다(예: SCR-214 점수 저장 → SCR-203 참석 목록의 점수·'점수 미설정 N명' 갱신, SCR-213 게스트 저장 → SCR-203에서 바로 참석 체크). 성공 알림은 3장 '토스트' 규칙을 따릅니다.
- **취소·닫기 확인**: 바뀐 값이 있는 시트를 ✕·바깥 누르기·Esc·뒤로 가기로 닫으려 하면 입력 중 닫기 확인 창(CMP-022)을 띄웁니다('계속 입력' / '닫기'). 바뀐 값이 없거나 즉시 저장형 시트(SCR-203 참석 체크, SCR-204 옵션, SCR-224 참가자)는 확인 없이 닫습니다.
- **저장 실패**: 시트를 닫지 않고 시트 위쪽에 안내 상자(CMP-023)로 원인과 다음 행동을 보여 주며 입력값을 유지합니다(3장 '오류 표시'). 충돌(ST6)은 3장 '충돌 안내'를 따릅니다.
- **예외(SCR-226)**: 대체 선수 지정 시트는 '반영'에 성공하면 닫히고, '반영'하지 않고 닫으면 확인 창 "대체 선수를 정하지 않으면 제외가 취소됩니다" 후 제외 자체를 되돌립니다(`02` SCR-226 시트 동작, AC-078). 이 동작은 위 '취소·닫기 확인'보다 우선합니다.
- **탭바·고정 버튼과의 관계**: 시트는 하단 탭바와 화면의 하단 고정 바·오른쪽 아래 주 버튼을 덮고 열립니다(그동안 아래 요소는 누를 수 없음). 시트의 하단 고정 버튼(저장·반영)은 안전 영역 위에 두고, 시트 내용 끝에 버튼 높이만큼 여백을 둡니다. 키보드가 올라오면 입력칸과 하단 고정 버튼이 키보드에 가리지 않게 시트 안을 스크롤합니다.
- **높이**: 화면마다 `02`에 정한 `height`(내용 높이·70%·전체)를 쓰고, 끌어올려 전체로 펼칠 수 있는 시트는 `02`에 적힌 곳만입니다. 시트 너비는 열 너비와 같습니다.
