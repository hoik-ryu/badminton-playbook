# AC-013 게스트 삭제 비식별화 — 변경 제안·영향 분석

- 작성: 2026-11-12 (I3-a 구현 중)
- 상태: **제안(승인 문서 미반영)**. 승인 문서·해시·`state.yaml`은 바꾸지 않았습니다. 기획 개정(r5 등)에서 AC-013 문구 반영 여부를 결정해 주세요.
- 근거: 사용자 결정 U5(2026-11-12) "게스트 삭제 시 이름·급수 모두 비식별화, 과거 경기에는 '삭제된 게스트' 표시"

## 1. 승인 AC와 차이

| 구분 | 승인 AC-013(r3) | 구현(이번 변경) |
|---|---|---|
| 지난 기록 표시 | 이름 대신 '삭제된 게스트' | 같음 |
| 급수 | "G의 급수도 함께 지워집니다" | 지움(`grade = NULL`) — **I1에서 빠져 있던 부분을 바로잡음** |
| 이름 | 정의 없음(I1은 보관) | **지움(`name = NULL`)** — 승인 AC보다 넓음(U5) |
| 성별·점수 | 정의 없음 | **보관**(아래 §3) |
| 행·id·참조 | 소프트 삭제(D2) | 같음. 청백전 참가·경기 기록의 참조 유지 |
| 이미 삭제된 게스트 | - | **소급 적용**(마이그레이션 0006이 이름·급수를 지움) |

## 2. 변경 내용

- DB(리비전 `0006_anonymize_deleted_guests`)
  - `guests.name`·`guests.grade` NULL 허용
  - `ck_guests_grade`: `grade IS NULL OR grade IN (...)`
  - 새 `ck_guests_deleted_anonymized`: 삭제 전에는 이름·급수 필수, 삭제 후에는 둘 다 NULL(DB가 상태를 보장)
  - 소급: `UPDATE guests SET name = NULL, grade = NULL WHERE deleted_at IS NOT NULL`
  - downgrade: 지운 값은 복구할 수 없어 자리표시자('삭제된 게스트'·'입문자')로 채움(**데이터 손실은 되돌아오지 않음**)
- API: `DELETE /api/roster/guests/{id}`가 `deleted_at`·`deleted_by_id` 기록과 함께 이름·급수를 지움. 명단(`GET /api/roster`)은 삭제된 게스트를 계속 보이지 않음(변경 없음).
- 청백전 응답: 삭제된 게스트는 `name: '삭제된 게스트'`, `grade: null`(점수·성별은 운영진 응답에만, 회원 응답 분리는 I3-d).

## 3. 성별·점수를 남긴 이유(결정 필요 시 알려 주세요)

- 성별: 지난 경기의 성별 균형 표시·집계(남/여 수)에 쓰이고, 그 자체로 사람을 특정하기 어려움.
- 점수(운영진 평가): 지난 경기의 실력차 표시(운영진 화면)에 쓰임. 회원 응답에는 원래 없음(AC-017·066).
- 둘 다 지우려면: NULL 허용 + CHECK 확장 + 실력차 '계산 불가' 표시가 늘어남. 원하시면 별도 리비전으로 추가합니다.

## 4. 영향 분석

| 대상 | 영향 | 처리 |
|---|---|---|
| I1 명단 API | 삭제 응답 204 그대로. 삭제된 게스트는 원래 목록에 없음 | 회귀 테스트 통과 |
| I1 테스트 | `test_roster.py`가 "삭제 후 이름 보관"을 확인하던 부분 → "이름·급수 NULL, 성별·점수 보관"으로 갱신(다른 확인은 그대로) | 갱신 |
| I1 DB 테스트 | 정리 쿼리가 이름 접두사 기준 → 삭제된 게스트는 이름이 없어 id 목록으로도 정리. 비식별화 CHECK 확인 추가 | 갱신 |
| 영속 개발 DB `smapsh` | 0006 적용 시 이미 삭제된 게스트의 이름·급수가 **되돌릴 수 없게** 지워짐 | **미적용**. 적용 전 `pg_dump` 백업 + 사용자 승인 필요 |
| FE Mock | Mock은 게스트 행을 지우고 지난 기록에 '삭제된 게스트' 표시(원래 같은 결과) | 변경 없음 |
| FE 타입 | 청백전 API 전환(I3-d) 시 `Person.grade`가 null일 수 있음 | I3-d에서 타입·표시 처리 |
| 감사 추적 | 누가 언제 지웠는지(`deleted_by_id`·`deleted_at`)는 남음. 누구였는지는 남지 않음 | U5 결정대로 |
| 게스트 복구 | 삭제 후 되살리기 기능은 원래 없음. 같은 사람이 다시 오면 새 게스트로 등록 | 변경 없음 |

## 5. 승인 문서 반영 제안(문구 초안)

> AC-013 (r5 제안): 운영진이 게스트 G를 삭제하면 명단에서 사라지고, 지난 경기 기록에는 '삭제된 게스트'로 표시됩니다. G의 **이름과 급수는 함께 지워지며** 되돌릴 수 없습니다. 지난 경기의 승패·경기 수는 그대로 남습니다.

## 6. 삭제된 게스트의 성별·점수 — 보존 필요성 분석(I3-b, 2026-11-12)

| 사용처 | 성별 | 점수 | 삭제 시 영향 |
|---|---|---|---|
| 승패·경기 수·순위·팀 승수 | 안 씀 | 안 씀 | 없음 |
| 랭크(C-07) | 안 씀(게스트는 랭크 없음) | 안 씀 | 없음 |
| 대진 생성(I3-b) | 씀 | 씀 | **없음** — 삭제된 게스트는 확정 전 청백전에서 빠지고(C-26) 새 참가 불가(U6) |
| 지난 경기 실력차(운영진 화면, C-24) | - | 씀 | 그 게스트가 낀 경기의 실력차가 '계산 불가'로 바뀜 |
| 지난 경기 성별 완화 표시 | 저장된 `gender_relaxed` 열 사용(재계산 안 함) | - | 없음 |
| 완화 사유 재판정(`relaxations`) | 씀 | 안 씀 | 사유가 바뀔 수 있음(판정 생략으로 처리 가능) |
| 참가 요약(남/여 수) | 씀(확정 전만 의미) | - | 지난 청백전 요약 수치가 달라짐 |

- **회원 노출 점검**: 회원 권한으로 열리는 API는 `/api/auth/me`·`/api/me/profile`·`/api/me/tutorial`뿐이며 게스트·평가 점수를 다루지 않음. 청백전·명단의 모든 경로(OpenAPI 전체 열거)가 회원에게 403인지 테스트로 고정(`test_member_cannot_reach_any_clubmatch_or_roster_route`). 회원용 청백전 API(I3-d)는 점수·실력차·급수 없는 별도 스키마로 만들 예정(AC-066).
- **결론**: 기록 보존에 꼭 필요한 값은 아님. 점수는 운영진 화면의 지난 실력차 표시에만, 성별은 요약·완화 사유 재판정에만 쓰임.
- **선택지**(결정 요청, 승인 전 마이그레이션·삭제 안 함):
  - A. 현행 유지(성별·점수 보관) — 운영진 화면 그대로
  - B. 점수만 삭제 — 운영진 평가(민감도 높음)를 지움, 지난 실력차 일부 '계산 불가'. `guests.score`는 이미 NULL 허용이라 **스키마 변경 없이** 삭제 처리 + 소급 UPDATE 리비전 1개
  - C. 성별·점수 모두 삭제 — `guests.gender` NULL 허용 + CHECK 수정 + 응답 `gender: null` 처리(FE 타입) + 완화 사유 판정 생략

## 7. C안 채택(사용자 결정 2026-11-12) — 구현·검증 결과

- 리비전 **0008**(`anonymize_guest_gender_and_score`): `guests.gender` NULL 허용, `ck_guests_gender`(NULL 또는 남/여), `ck_guests_deleted_anonymized`(삭제 전 이름·급수·성별 필수 / 삭제 후 이름·급수·성별·점수 모두 NULL), 이미 삭제된 게스트 소급. downgrade는 성별 자리표시자('남')로 채움(**원래 값 복구 불가**).
- API: 게스트 삭제가 성별·점수도 지움. 청백전 응답에서 삭제된 게스트는 `name '삭제된 게스트', gender/grade/score null`.
- 검증된 영향(테스트 `test_deleted_guest_c_plan_effect_on_history`):
  - 그대로: 경기 결과, 참가 관계, 사람별 경기 수, 순위(승수·공동 순위), 팀 승수, 저장된 성별 완화·사유(생성·교체 때 저장 → 성별이 지워져도 바뀌지 않음)
  - 바뀜: 그 게스트가 낀 지난 경기의 **실력차 → '계산 불가'(null)**(운영진 화면). 다른 경기는 그대로
  - 영향 없음: 대진 생성(삭제된 게스트는 확정 전 청백전에서 빠짐, C-26), 교체(삭제된 게스트는 대체로 못 들어감)
- 임시 PostgreSQL: 소급(성별·점수 NULL), CHECK 거부(삭제됐는데 성별/점수 남음, 삭제 전 성별 없음), 왕복 확인. **`smapsh` 미적용**.
