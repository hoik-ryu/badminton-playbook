# PRD: badminton-playbook

## 1. 배경 (Background)

배드민턴 동호회에는 다음과 같은 문제가 있습니다.

- 복식 로테이션을 잘 몰라서 경기 중에 헤매는 회원이 있습니다(PRB-001).
- 운영진은 지금 ChatGPT로 대진을 짭니다. 그런데 오류가 생기거나 같은 경기가 반복되기도 합니다(PRB-002).
- 실력, 성별, 게임 수, 중복 여부를 동시에 맞추기가 어렵습니다(PRB-003).
- 청백전 결과를 기록하고 랭크로 연결할 수단이 없습니다(PRB-004). 지금은 로테이션 학습에도, 청백전 기록에도 체계적인 수단이 없습니다(Q-010 해결).

badminton-playbook은 이 문제를 이렇게 해결합니다.

- 회원(PER-001)에게는 로테이션 학습을 제공합니다.
- 운영진(PER-002)과 슈퍼 관리자(PER-003)에게는 정확한 알고리즘으로 짜는 실시간 대진과 청백전 랭크 관리를 제공합니다.

기준 문서: `01-discovery.md` r2(승인됨).

## 2. 목표와 비목표 (Goals / Non-Goals)

### 목표

- **GOAL-001**: 운영진이 ChatGPT 대신 이 서비스로 정확한 대진을 짭니다.
  - 목표치: 런칭 후 1개월 동안 정기 운동 대진의 100%를 서비스로 생성하고, 같은 날 중복 경기는 0건입니다.
- **GOAL-002**: 회원이 복식 로테이션을 이해합니다.
  - 목표치: 런칭 후 1개월 안에 승인 회원의 50% 이상이 학습 페이지를 1회 이상 방문합니다(접속 로그로 측정, Q-013 해결).
- **GOAL-003**: 청백전 결과를 회원 랭크로 관리합니다.
  - 목표치: 청백전 경기의 100%에 승패를 기록합니다(Q-013 해결).

### 비목표

- 회원이 직접 참석을 등록하거나 알림을 받는 기능은 만들지 않습니다.
- 여러 동호회를 운영하는 기능은 만들지 않습니다.
- AI(LLM)로 대진을 생성하거나 추천하지 않습니다.
- 학습 진도와 퀴즈 결과는 저장하지 않습니다.

## 3. 사용자 (Users)

| 사용자 | 사용 범위 | 화면 |
|---|---|---|
| PER-001 회원 | 로테이션 학습, 마이페이지 | 모바일 전용 |
| PER-002 운영진 | 회원·게스트·점수 관리, 실시간 대진, 청백전 | PC·모바일 반응형 |

| FR-019 | **마이페이지**: 회원이 프로필(이름, 성별)을 보고 수정합니다. 본인 랭크와 청백전 전적(경기 수, 승, 패, 승률)도 봅니다. 1–10 점수는 보이지 않습니다. | Must | PRB-004, PER-001, GOAL-003 |
| FR-020 | **회원 비활성 처리** *(r2 신규, Q-018)*: 운영진이 회원을 비활성 처리하거나 다시 활성화합니다. 비활성 회원은 참석 목록에서 숨겨지고 로그인해도 회원 기능을 쓸 수 없지만, 청백전 기록은 유지됩니다. | Should | PRB-003, PER-002, GOAL-001 |
| FR-021 | **대진 수동 교체** *(r2 신규, FR-011에서 분리)*: 확정 전에 운영진이 경기 속 선수를 대기자나 다른 경기의 선수와 맞바꿉니다. | Should | PRB-002, PER-002, GOAL-001 |

## 7. 가정 (Assumptions)

### 7.1 사용자가 확인한 사항 (planning r2)

r1에서 가정이나 미결 질문이었던 항목 중, 사용자가 선택형 질문으로 직접 확인한 내용입니다. 이 항목들은 더 이상 가정이 아닙니다.

| 확정 ID | 내용 | 근거 | 반영 위치 |
|---|---|---|---|
| C-01 | **레벨별 방식**: 점수를 상(8–10), 중(5–7), 하(1–4) 3구간으로 나누고, 같은 구간 안에서 4명씩 코트를 채웁니다. 4명 단위로 맞지 않으면 인접 구간에서 점수가 가장 가까운 사람으로 채웁니다. 무작위 방식은 점수와 관계없이 4명씩 묶습니다. | ASM-007 → 수정 확인 | FR-008 |
| C-02 | **밸런스**: 두 팀의 점수 합 차이가 가장 작게 팀을 나눕니다. | ASM-008 확인 | FR-008 |
| C-03 | **성별 조합(혼복 우선)**: 혼복(각 팀 남 1·여 1)을 가능한 한 많이 만들고, 남는 인원으로 남복이나 여복을 만듭니다. 그래도 맞출 수 없을 때만 불균형 조합을 허용하고, 그 경기에 '성별 규칙 완화'를 표시합니다. | ASM-009 → 수정 확인 | FR-008, FR-010, FR-013 |
| C-04 | **게임 수 공평성**: 그날 게임 수가 적은 사람을 먼저 출전시킵니다. 게임 수가 같으면 직전 라운드 대기자, 그다음 참석 체크 순서를 따릅니다. | ASM-010 확인 | FR-008, FR-009 |

## 9. 릴리스 기준 (Release Criteria)

1. Must FR(FR-001–012, FR-014–019, 총 18개)에 연결된 AC가 `05-acceptance-criteria.md`에서 모두 통과해야 합니다.
2. 참석자 20명, 코트 4면 기준으로 5라운드를 연속 생성했을 때, 같은 날 같은 경기가 0건이어야 하고(NFR-003) 각 라운드를 2초 안에 생성해야 합니다(NFR-004).
3. 회원 권한으로는 어떤 화면과 API에서도 1–10 점수가 노출되지 않아야 합니다(NFR-005).
4. 카카오 개발자 앱 등록을 마치고, 카카오톡 인앱 브라우저에서 로그인이 동작해야 합니다(FR-001, NFR-007).
5. 학습 콘텐츠 4개 주제와 각 주제의 퀴즈를 운영진이 검수해야 합니다(FR-017, FR-018).
