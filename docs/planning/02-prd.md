# PRD: badminton-playbook

> **r3 개정**: Discovery r3(승인됨)를 기준으로 PF-001~006을 반영했습니다. 정책 결정과 질문·답변 원문은 `.ai-workflow/discovery-notes.md`의 '기획 재검토' 절(정책 확인 1–13차)에 있습니다. (r3) 표시는 이번에 바뀐 내용입니다. ID는 재사용하거나 다시 매기지 않았고, 폐기한 항목은 취소선으로 남겼습니다.

## 1. 배경 (Background)

배드민턴 동호회에는 다음과 같은 문제가 있습니다.

- 복식 로테이션을 잘 몰라서 경기 중에 헤매는 회원이 있습니다(PRB-001).
- 운영진은 지금 ChatGPT로 대진을 짭니다. 그런데 오류가 생기거나 같은 경기가 반복되기도 합니다(PRB-002).
- 실력, 성별, 게임 수, 중복 여부를 동시에 맞추기가 어렵습니다(PRB-003).
- 청백전 결과를 기록하고 랭크로 연결할 수단이 없습니다(PRB-004). 지금은 로테이션 학습에도, 청백전 기록에도 체계적인 수단이 없습니다(Q-010 해결).

badminton-playbook은 이 문제를 이렇게 해결합니다.

- 회원(PER-001)에게는 (r3) 게임형 로테이션 튜토리얼과 확정된 청백전 조회를 제공합니다.
- 운영진(PER-002)과 슈퍼 관리자(PER-003)에게는 정확한 알고리즘으로 짜는 실시간 대진, (r3) 같은 알고리즘으로 만드는 청백전(개인전·팀전) 대진과 결과·랭크 관리를 제공합니다.

기준 문서: `01-discovery.md` r3(승인됨).

## 2. 목표와 비목표 (Goals / Non-Goals)

### 목표

- **GOAL-001**: 운영진이 ChatGPT 대신 이 서비스로 정확한 대진을 짭니다.
  - 목표치: 런칭 후 1개월 동안 정기 운동 대진의 100%를 서비스로 생성하고, 같은 날 중복 경기는 0건입니다.
- **GOAL-002**: 회원이 복식 로테이션을 이해합니다.
  - (r3) 목표치: 런칭 후 1개월 안에 튜토리얼 권장 대상(1–10 실력 점수 3 이하 또는 미설정인 승인 회원, C-23)의 50% 이상이 '튜토리얼 난이도 · 입문자' 스테이지를 1개 이상 통과합니다. 서버에 저장한 통과 데이터로 측정합니다(FR-026).
- **GOAL-003**: 청백전 결과를 회원 랭크로 관리합니다.
  - (r3) 목표치: 출시 후 첫 30일 동안 확정된 청백전의 종료 처리율 100%. 분모는 이 기간에 확정되었고 청백전 날짜가 30일째보다 앞선 청백전, 분자는 그중 30일째가 끝날 때까지 종료된 청백전입니다. 청백전 날짜가 30일째인 청백전은 '진행 중 N건'으로 따로 보고하고, 날짜가 지났는데 종료되지 않은 청백전은 미달로 셉니다. 종료는 모든 확정 경기의 결과가 기록된 뒤에만 가능하므로(C-20) 결과 기록률 100%도 함께 보장됩니다.

### 비목표

- 회원이 직접 참석을 등록하거나 알림을 받는 기능은 만들지 않습니다.
- 여러 동호회를 운영하는 기능은 만들지 않습니다.
- AI(LLM)로 대진을 생성하거나 추천하지 않습니다.
- ~~학습 진도와 퀴즈 결과는 저장하지 않습니다.~~ (r3에서 비목표 해제: 튜토리얼 통과 여부·최고 점수·최초 통과 시각은 저장, FR-026)
- (r3) 튜토리얼의 상황별 선택 기록은 저장하지 않습니다.
- (r3) 회원이 청백전에 직접 참가 신청하는 기능은 만들지 않습니다.

## 3. 사용자 (Users)

| 사용자 | 사용 범위 | 화면 |
|---|---|---|
| PER-001 회원 | (r3) 로테이션 튜토리얼, 확정된 청백전 조회, 마이페이지 | 모바일 전용 |
| PER-002 운영진 | 회원·게스트·점수 관리, 실시간 대진, 청백전(생성·대진·확정·결과), (r3) 튜토리얼 권장 대상 관리 | PC·모바일 반응형 |
| PER-003 슈퍼 관리자 | 운영진 기능 전체 + 운영진 지정·해제 | PC·모바일 반응형 |
| PER-004 게스트 | 로그인하지 않음. 대진과 청백전에 포함됨 | 없음 |

운영진과 슈퍼 관리자도 회원 기능(튜토리얼, 청백전 조회, 마이페이지)을 쓸 수 있다고 가정합니다(ASM-020).

## 9. 릴리스 기준 (Release Criteria)

1. (r3) Must FR(FR-001–012, FR-014–016, FR-019, FR-022–026, 총 21개)에 연결된 AC가 `05-acceptance-criteria.md`에서 모두 통과해야 합니다.
2. 참석자 20명, 코트 4면 기준으로 5라운드를 연속 생성했을 때, 같은 날 같은 경기가 0건이어야 하고(NFR-003) 각 라운드를 2초 안에 생성해야 합니다(NFR-004).
3. (r3) 회원 권한으로는 어떤 화면과 API에서도 NFR-005의 비공개 항목(1–10 점수, 팀 점수 합, 실력차, 튜토리얼 권장 대상 여부, 다른 회원의 급수·지인·튜토리얼 진행·랭크, 확정 전 청백전)이 노출되지 않아야 합니다. 회원 API 계약 테스트로 확인합니다.
4. 카카오 개발자 앱 등록을 마치고, 카카오톡 인앱 브라우저에서 로그인이 동작해야 합니다(FR-001, NFR-007).
5. (r3) MVP1 튜토리얼 30상황(입문자·왕초보 각 3스테이지 × 5상황)을 운영진(또는 코치)이 검수해야 합니다(FR-025, C-22).
6. (r3) QA 기기 목록의 카카오톡 인앱 브라우저에서 튜토리얼이 NFR-008을 만족해야 합니다.
