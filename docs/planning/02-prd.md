## 1. 배경 (Background)

배드민턴 동호회에는 다음과 같은 문제가 있습니다.

- 복식 로테이션을 잘 몰라서 경기 중에 헤매는 회원이 있습니다(PRB-001).
- 운영진은 지금 ChatGPT로 대진을 짭니다. 그런데 오류가 생기거나 같은 경기가 반복되기도 합니다(PRB-002).
- 실력, 성별, 게임 수, 중복 여부를 동시에 맞추기가 어렵습니다(PRB-003).
- 청백전 결과를 기록하고 랭크로 연결할 수단이 없습니다(PRB-004). 지금은 로테이션 학습에도, 청백전 기록에도 체계적인 수단이 없습니다(Q-010 해결).

badminton-playbook은 이 문제를 이렇게 해결합니다.

- 회원(PER-001)에게는 (r3) 게임형 로테이션 튜토리얼과 확정된 청백전 조회를 제공합니다. (r7) 튜토리얼은 셔틀콕이 날아오는 상황을 보고 코트 위 번호로 이동할 위치를 고르는 상황 판단형 학습으로 개편합니다.
- 운영진(PER-002)과 슈퍼 관리자(PER-003)에게는 정확한 알고리즘으로 짜는 실시간 대진, (r3) 같은 알고리즘으로 만드는 청백전(개인전·팀전) 대진과 결과·랭크 관리를 제공합니다.

기준 문서: `01-discovery.md` ~~r3~~ (r7) r4(승인됨).

## 2. 목표와 비목표 (Goals / Non-Goals)

### 목표

- **GOAL-001**: 운영진이 ChatGPT 대신 이 서비스로 정확한 대진을 짭니다.
  - 목표치: 런칭 후 1개월 동안 정기 운동 대진의 100%를 서비스로 생성하고, 같은 날 중복 경기는 0건입니다.
- **GOAL-002**: 회원이 복식 로테이션을 이해합니다.
  - ~~(r3) 목표치: 런칭 후 1개월 안에 튜토리얼 권장 대상(1–10 실력 점수 3 이하 또는 미설정인 승인 회원, C-23)의 50% 이상이 '튜토리얼 난이도 · 입문자' 스테이지를 1개 이상 통과합니다. 서버에 저장한 통과 데이터로 측정합니다(FR-026).~~
  - (r7) 지표 정의는 승인된 Discovery r4 6장의 GOAL-002('튜토리얼 난이도 · 왕초급' 과정 통과율, 첫 30일 기준선)를 그대로 따릅니다(C-30).
  - (r7, 초안 수정) **이번 MVP는 이 지표를 집계·보고하는 기능을 만들지 않습니다.**
    - 제외: 30일 집계, 스냅샷, 보고서, 성과 분석용 API·DB·배치 작업
    - 제품 요구는 회원 개인의 단계별 진행률·완료 여부 표시(FR-026)와 스테이지 70% 통과 판정(C-22)까지입니다.
    - 지표를 실제로 측정할지, 언제 어떻게 측정할지는 제품 소유자가 필요할 때 정합니다.

  - 스테이지 통과 기준 70%(C-22)와 GOAL-002 과정 통과율은 다른 개념입니다.
- **GOAL-003**: 청백전 결과를 회원 랭크로 관리합니다.
  - (r3) 목표치: 출시 후 첫 30일 동안 확정된 청백전의 종료 처리율 100%. 분모는 이 기간에 확정되었고 청백전 날짜가 30일째보다 앞선 청백전, 분자는 그중 30일째가 끝날 때까지 종료된 청백전입니다. 청백전 날짜가 30일째인 청백전은 '진행 중 N건'으로 따로 보고하고, 날짜가 지났는데 종료되지 않은 청백전은 미달로 셉니다. 종료는 모든 확정 경기의 결과가 기록된 뒤에만 가능하므로(C-20) 결과 기록률 100%도 함께 보장됩니다.

### 7.3 튜토리얼 콘텐츠 작성·검수 기준 *(r7 신규, 초안 수정 반영)*

40개 상황의 실제 내용은 이 문서에서 확정하지 않습니다. 사용자가 확정한 방식(Q-028)은 다음과 같습니다.

- **초안**: AI를 활용해 40개 상황의 초안을 작성합니다.
- **검수**: 최종 콘텐츠의 배드민턴 전술적 타당성은 제품 소유자가 직접 검수합니다. 외부 코치, 별도 운영진, 검수 조직의 승인은 필수 조건이 아닙니다.
- **관리 방식**: 검수 완료 여부는 개발 과정의 간단한 체크리스트로 관리합니다. 검수 시스템, 관리자 승인 워크플로, 콘텐츠 데이터 안의 검수 기록 필드는 만들지 않습니다.
- **사용자 의견**: 일반 사용자의 의견은 출시 후 개선 제안으로 받을 수 있지만, 배포 전 필수 절차는 아닙니다.

**① 상황 데이터 항목**: 상황마다 아래 항목을 적습니다. '전술 검토'가 '예'인 항목은 제품 소유자가 실제 경기 기준으로 확인합니다.

| 항목 | 내용 | 전술 검토 |
|---|---|---|
| 상황 ID·스테이지 | 소속 스테이지(C-27)와 순번 | — |
| 상황 설명 | 한 줄. 코트 그림의 대체 글자로도 씀 | — |

| 예상 학습 시간 | 스테이지 단위, 분 | — |

**② 작성 기준**: 40개 상황은 실제 플레이에서 의미 있는 학습 목표와 정답·해설을 갖춰야 합니다.

- 스테이지의 5개 상황은 모두 그 스테이지의 학습 목표(C-27)를 다룹니다.
- 5개 상황은 서로 달라야 합니다. 시작 배치, 셔틀콕 방향, 파트너 위치 중 하나 이상이 다르고, 해설의 판단 근거도 달라야 합니다. 좌우나 번호만 바꾼 상황은 같은 상황으로 봅니다.
- 왕초급·초급 스테이지에는 셔틀콕 방향 칸과 정답 칸이 다른 상황을 적어도 1개 넣고, 해설에서 그 차이를 설명합니다(특히 '담당 영역 나누기').
- 기존 30개 초안 상황은 주제와 아이디어의 재료로만 씁니다. 좌표를 칸 번호로 단순 변환해 옮기지 않습니다.
- 해설은 입문자도 이해할 수 있는 말로 한두 문장으로 씁니다.
- 입문자 문제는 전술 판단 없이 코트 구조, 번호, 기본 자리, 복귀만 다룹니다.

**③ 검수 체크리스트(개발용)**: 스테이지마다 아래를 확인하고 체크리스트에 표시합니다. 하나라도 빠진 스테이지는 배포하지 않습니다(릴리스 기준 5).

1. 학습 목표와 5개 상황이 맞고, 서로 다른 상황인가(② 기준)
2. 시작 배치, 셔틀콕, 정답 칸, 허용 칸, 파트너 이동이 실제 복식 전술에 맞는가(제품 소유자 판단)
3. 해설이 정답 이유와 오답 이유를 분명히 설명하는가
4. 실제로 플레이해 보았을 때 애니메이션과 판정이 해설과 맞는가
5. 형식 자동 검사(AC-117)를 통과했는가

'③-5 형식 자동 검사'는 정답 칸 1개, 칸 번호 범위, 허용·정답 중복 없음, 해설 존재, 스테이지당 5상황, 서버 레지스트리와의 일치를 봅니다(NFR-009).
