# frontend-design 브리프 (SMAPSH)

Anthropic 공식 `frontend-design` 스킬(v1.1.1)에 주는 브리프입니다. 스킬은 "브리프가 시각 방향을 정했으면 그 말을 그대로 따른다"고 되어 있으므로, 고정 규칙을 먼저 적고 스킬이 제안해도 되는 자유 요소를 따로 적습니다. 스킬의 제안은 권위 순서 6위이며 `visual-decisions.md`에 **VD 후보**로만 기록합니다.

## 1. 주제

- **서비스**: SMAPSH — 배드민턴 동호회 운영 앱. 운영진은 회원 명단·점수, 운동 당일 실시간 대진, 청백전을 관리하고, 회원은 게임형 로테이션 튜토리얼과 확정된 청백전·자기 기록을 봅니다.
- **동호회**: 주 1회 일요일 정기모임(사용자 확인, 2026-11-10).
- **화면 성격**: 마케팅 페이지가 아니라 업무용 앱 화면입니다. 히어로 영역, 큰 숫자 통계 띠, 장식용 그라데이션 같은 랜딩 페이지 요소를 넣지 않습니다.

## 2. 사용자와 사용 환경

| 사용자 | 환경 | 시각 요구 |
|---|---|---|
| 운영진(PER-002·003) | 체육관 현장, 휴대폰 한 손 조작, 밝은 조명, 짧은 틈에 빠르게 조작. PC는 사전 준비 | 큰 터치 영역, 한눈에 읽히는 숫자, 주요 행동은 엄지 영역 |
| 회원(PER-001) | 카카오톡 인앱 브라우저, 휴대폰 세로 화면 | 모바일 레이아웃만, PC에서도 최대 480px |

## 3. 고정 규칙(스킬이 바꿀 수 없음)

- 승인 문서: Planning r4, UX Planning r2(UXD 63개), UX Specification r1(`docs/design/01`–`05`).
- 화면 구성, 정보와 우선순위, 문구, 행동, 상태(ST1–ST6과 고유 상태), 접근 권한은 `02-screens.md` 그대로입니다. 승인되지 않은 기능·화면 요소를 추가하지 않습니다.
- 토큰 값(색, 간격, 반경, 크기, 글꼴 크기, 모션)은 `tokens.json`(= 승인된 04) 그대로입니다. 새 색을 만들지 않습니다. 스킬의 '4–6개 hex 팔레트' 단계는 이미 승인된 토큰으로 대신합니다.
- 접근성: 본문 대비 4.5:1, 큰 글자·경계 3:1, 색만으로 구분하지 않음, 터치 최소 44px(주요 버튼 48px), 보이는 레이블, 포커스 표시, `prefers-reduced-motion`.
- 승인된 표기 형식을 유지합니다. 예: 명단 행 '김민수 · 남 · C조 · 7점'(UXD-074). 스킬은 가운뎃점 표기를 진부한 패턴으로 보지만 UXD가 우선합니다.
- 배치 결정 유지: '게스트 추가'는 모바일 오른쪽 아래, PC는 목록 위(UXD-026). 하단 탭·PC 왼쪽 메뉴(UXD-066). 팀 표기 '청팀/백팀', '1팀/2팀'(C-24).
- 컴포넌트는 04의 CMP 25개를 재사용합니다(`component-mapping.md`).
- 기술: Tailwind v4, shadcn/ui + Radix, Lucide, Pretendard(VD-001).

## 4. 자유 요소(스킬이 VD 후보로 제안 가능)

- 글꼴 세부: Pretendard의 굵기 조합, 숫자 표기(고정폭 숫자), 자간·행간(토큰 범위 안).
- 아이콘: Lucide 중 어떤 아이콘을 쓰는지, 크기와 선 굵기.
- 컴포넌트 치수: 패딩, 행 높이, 칩·배지의 높이와 안쪽 여백(토큰의 space·radius 범위 안).
- 시각 상태 표현: 눌림·포커스·선택·비활성의 표현(토큰 색 안에서).
- PC 열 너비와 정렬, 스켈레톤의 모양.
- 절제된 강조 한 곳: 스킬의 원칙대로 "대담함은 한 곳에만". SMAPSH에서는 운영진이 가장 자주 확인하는 정보(예: 점수 숫자)에만 강조를 둡니다.

## 5. 금지

- 스킬이 피하라고 한 기본값(크림 배경 + 테라코타, 형광 강조, SaaS 카드 키트 장식, 모든 제목 위 대문자 라벨 등)은 SMAPSH에서도 쓰지 않습니다.
- 사용자가 누르지 않았는데 움직이는 장식 애니메이션을 넣지 않습니다(모션 토큰은 상태 변화와 시트 전환용).
- 실제 개인정보를 샘플로 쓰지 않습니다(`figma.md` 4장).

## 6. 산출물 처리

스킬의 계획(타이포·레이아웃·원칙)과 자기 비평 결과는 `visual-decisions.md`에 VD 후보로 기록합니다. 사용자가 승인한 VD만 Figma와 Preview에 씁니다. 토큰 값이나 화면 정보·행동이 바뀌는 제안은 VD가 아니라 UX 설계 변경(`/product-design reopen --stage ux_spec`)으로 처리합니다.
