### 1.1 shadcn/ui 공식 CLI 점검
1. **`init` 리허설**: 임시 복사본(scratchpad)에서 실행했습니다. 변경은 리허설 폴더 안에서만 일어났고, 결과는 아래와 같았습니다.
   - `components.json`, `src/lib/utils.ts`, `src/components/ui/button.tsx` 생성
   - `src/index.css`를 무채색 oklch 테마로 덮어씀
   - 의존성 추가: `@fontsource-variable/geist`, `cn`, `radix-ui`. 모두 `^` 범위
2. **예상하지 못한 점**
   - 새 패키지 `cn` 0.5.2: shadcn 관리, 공개 8일째, 설치 스크립트 없음
   - Geist 글꼴이 Pretendard와 충돌
   - 무채색 테마로 덮어씀
   - 실행 스크립트나 폴더 밖 변경은 없었습니다. 그래서 **중단 조건에는 해당하지 않는다**고 판단했습니다.
3. **처리**
   - 실제 폴더에서는 `init`을 쓰지 않았습니다.
   - `components.json`은 리허설에서 나온 것과 같은 내용을 두었습니다.
   - `add`만 공식 CLI로 실행하되, 먼저 `--dry-run`과 `--view`로 확인했습니다. 대상은 `src/components/ui/` 새 파일 5개와 의존성 `cn`이었고, 코드가 불러오는 모듈은 react, cva, cn, radix-ui뿐이었습니다.
   - `cn`은 정확한 버전으로 고정했습니다.
4. **사용 가능성 판단**
   - Toggle, Input, Badge, Button은 감싸는 컴포넌트에서 `className`만 덮어써서 썼습니다.
   - Switch는 nova가 크기를 `data-[size=*]` 변형으로 고정해서 덮어쓰기가 먹지 않았습니다. 그래서 **부품 코드에 `lg`(44×24) 크기를 추가**했습니다(3줄).
   - 결론: 쓸 수는 있지만, nova의 기본 크기(32–36px)와 글자 크기(14px)가 04의 44/48·16px 기준과 다릅니다. 모든 부품에 덮어쓰기나 수정이 필요합니다.

## 2. 구현 요약

- 토큰
  - `tokens.json`(승인, 읽기 전용)과 `themes/c-mint-hybrid.json`(개발자 설정)을 `gen-tokens.mjs`가 합쳐 `tokens.css`를 만듭니다.
  - Tailwind 기본 색은 `--color-*: initial`로 비웠습니다. 토큰 밖 색 클래스는 아예 만들어지지 않습니다.
- 구조
  - 헤더 띠(뒤로 · 제목 · '게스트 추가' · 더보기)와 검색 띠는 B안 구조입니다. '게스트 추가' 상단 배치는 A안입니다.
  - 그 아래 순서: 필터 칩 → '비활성 포함' → 회원 11명 → '게스트' 머리글 → 게스트 2명 → 스크롤 안전 영역 → 고정 하단 탭(Lucide 아이콘 4개, '운영' 현재 탭)
- 추적: DOM 속성 `data-scr="SCR-211"`, `data-st="ST1"`, `data-cmp="CMP-0xx"`, `data-experimental="…"`
- dry-run IR의 쓰임: 컴포넌트 계층·변형·글자를 참고했고, 명단 순서는 자동으로 대조했습니다(일치, measured). 데이터 원본은 `figma.md` 4장 샘플 세트입니다. IR을 표준으로 확정하지는 않았습니다.

### 7.2 중립 화면 명세(IR)의 최소 필드(이번에 실제로 필요했던 것)
1. 화면·상태·플랫폼 ID(`SCR-211`, `ST1`, `mobile`)
2. 영역 목록과 **스크롤 동작**(헤더 스크롤 / 하단 탭 고정 / 스크롤 안전 영역). dry-run IR에는 없었고 구현 중에 정함
3. 노드: CMP ID + 변형 + 글자 속성 + **데이터 바인딩**(행 필드: 이름, 성별, 급수, 점수 | 없음)
4. 토큰은 **의미 이름**만(값 아님) + 테마 참조
5. 밀도 정책: 행 높이, 폭별 행 수 기준, 줄 간격
6. **보이는 크기와 누름 영역을 따로**(칩 32/44, 헤더 버튼 36/44). IR에 하나의 크기만 있으면 밀도가 깨짐(1차 결함)
7. 안전 영역 정책(가정값, `env()` 사용)
8. 접근성 이름 형식(C4)
9. 실험 표시 + 근거 명세 항목(UXD·CMP ID)
10. 문구 원본(명세 문구 / 자리 표시 여부)

### 7.3 React 렌더링에서 새로 드러난 UX 명세 공백
C1(칩 줄 간격과 누름 영역 겹침), C2(검색 보이는 레이블), C3(헤더 고정), C4(행 접근성 이름), C5(둥근 정도 토큰), 그리고 '튜토리얼 권장' 집계에 비활성 회원을 넣을지(샘플에서는 비활성이 기준 밖이라 판단하지 않았음).

### 7.4 자동 검증 / 사람의 시각 평가
| 자동(이번에 구현) | 사람이 필요 |
|---|---|
| 행 높이, 폭별 행 수, 고정 요소 가림(맨 아래·포커스), 터치(label·의사 요소 포함), 글자 대비(배경 합성), 비텍스트 대비(경계·아이콘·트랙), 부품 내부 넘침, 글자 넘침·줄바꿈, 렌더링 색·소스 색의 토큰 일치, 콘솔 오류, 글꼴 적용, IR과 DOM 대조 | 브랜드 인상(산뜻함·스포츠 클럽다움), 시각 위계와 강조 한 곳, 아이콘 의미 적합성(청백전 = swords?), 정렬의 미세한 어긋남, **처음 보는 유형의 결함**(스위치 결함은 사람이 먼저 찾고 나서 검사를 추가함) |

### 7.5 ai-product-workflow에 재사용할 수 있는 검증 로직
- `scripts/review.mjs`의 측정 함수
  - 밀도
  - 가림
  - 터치: `label[for]`, 감싼 label, `::before` 확장을 모두 반영
  - 대비: 반투명 배경 합성
  - 경계 대비: max(테두리, 채움)
  - 부품 내부 넘침
  - 팔레트 일치: 렌더링 색과 소스 색
  - IR 대조
- `scripts/gen-tokens.mjs`
  - 승인 토큰과 테마 파일을 합쳐 생성
  - `--color-*: initial`로 토큰 밖 색을 원천 차단
  - 팔레트 JSON을 검증 입력으로 냄
- 샌드박스 대응: Playwright 스크린샷이 멈추면 CDP `Page.captureScreenshot`으로 대체
- 외부 생성기(shadcn) 점검 절차: 임시 복사본 리허설 → `--dry-run`/`--view` → 폴더 밖 변경 0 확인 → 버전 고정
- 반복 규칙: 결함을 고칠 때 그 결함을 잡는 검사를 함께 추가하고, **원래 결함 코드로 다시 돌려 검사가 잡는지 확인**(이번 스위치 사례)

### 7.6 Figma-first와 비교
| 항목 | Figma-first(C안) | Code-first(이번) |
|---|---|---|
| 1개 화면에 든 외부 호출 | 프레임당 `use_figma` 몫 + 스크린샷(한도 포함) | 0(로컬) |
| 측정 | 노드 크기 + 계산 | 브라우저 측정 |
| 결함 발견 | 스크린샷을 사람이 봄 | 자동 0건이 될 때까지 3차 반복 + 사람 확인 1건 |
| 재현 | 스크립트를 MCP에 옮겨 적음(위험) | 저장소 파일 그대로 빌드 |
| 비용 | 월 한도 | 설치 약 600MB(브라우저), 측정 1회 약 20초 |
