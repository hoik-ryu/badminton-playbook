# V05-A 디자인 계획 — 떠 있는 시트형(SCR-102·103)

## 시각 개념
- 사용자 결정(2026-11-19): 코트 색은 기존 초록 `color.court.surface` #2F7D4F로 확정, 민트 코트 비교 제외. 좌표(0–61 × 0–134, 네트 67)·UXD-077 6칸·9칸 칸 좌표·상태 전환·학습 로직은 그대로 두고, V04-A(EXP-V04-A) 디자인 시스템을 화면 셸에만 적용한다.
- A는 V04-A의 "흰 카드 + 옅은 그림자" 언어를 그대로 옮긴다. SCR-102 아래 영역(질문·판정·버튼)을 위 모서리가 둥근 흰 시트로 코트 위에 띄우고, SCR-103은 점수·최고 점수·진행률·틀린 상황을 각각 흰 카드로 나눈다.
- 코트 오버레이는 07 후보 VD-026–031 값을 그대로 적용(격자 흰 70% 점선 0.35단위, 번호 4.6단위 + 바닥색 60% 원, 선택 흰 테두리 0.8/1.2 + 25% 채움, 판정 상태 bg 90% + 아이콘 + 선 모양, 셔틀 방향 흰 점선 고리 7단위, 동선 흰 실선 0.6 + 그림자 · 파트너 점선 0.4).

## 색·토큰
- V04-A 후보 테마(theme.json) 값 그대로: `color.action.primary` #0B9E8B(채움·아이콘), `color.text.accent` #10776C(강조 글자·작은 주 버튼), `color.accent.subtle` #DDF8EF(배지), `color.bg.page` #FAFFFD, 상태 success·warning·danger, 코트 `color.court.*`.
- 새 토큰 없음. 그림자·옅은 테두리는 토큰 색을 color-mix로 낮춘 값.

## 타이포그래피
- 질문·판정 제목 `font.size.title` 18 bold, 상황 설명 16 bold, 이유·배지 13. 큰 CTA(`primary`·56px) 22px bold(UX Spec r4 CMP-001). 결과 점수 `font.size.display` 32 + '/ 5' 18.
- 숫자는 고정폭(tabular-nums).

## 간격·밀도
- 좌우 16px, 아래 시트 패딩 16, 시트 높이 156px 고정(UXD-081: 단계가 바뀌어도 코트 크기 고정). 결과 카드 사이 12px.
- 시트를 높게 잡아 판정 이유 1–2줄과 버튼 한 줄이 스크롤 없이 들어가게 했다(대신 코트가 B보다 약간 작음).

## 컴포넌트 표현
- CMP-026: 56px, '✕ 나가기' + 과정·단계 + 민트 알약 '상황 n/5' + 회색 알약 'n점'.
- CMP-046: 기존 코트 그림 + 번호 격자 레이어(그리는 순서: 코트 → 격자 → 강조·판정 → 선수·셔틀 → 번호 → 누름 영역).
- CMP-001: 큰 CTA(primary-lg 22px), 작은 주 버튼(outline: 흰 바탕 + `color.text.accent` 글자·테두리, DD 4.1), 보조(secondary: surface 바탕). ST10 재생 컨트롤은 민트 칩(44px).
- CMP-022: 흰 둥근 대화상자, '취소'(surface)·'나가기'(danger).
- CMP-049: V04-A 배너 안 막대와 같은 8px 막대 + 숫자. CMP-030: 48px 행. CMP-023: danger 안내 상자 + '다시 저장'.

## 시각 계층·강조
- SCR-102: 코트(가장 큼) → 아래 시트의 질문/판정 → 상단 바 진행·점수. 판정은 코트 위 칸 표시와 아래 판정 제목(상태색 아이콘 원 + 글자)으로 두 번 보인다.
- SCR-103: 점수 카드(32px 숫자 + 통과 배지 + 기준) → 최고 점수 → 진행률 → 틀린 상황 → 아래 시트의 버튼(통과: '다음 스테이지' CTA, 미통과: '다시 하기' CTA).

## 진부한 기본값 대조
- 결과 화면을 '축하 일러스트 + 큰 원형 점수'로 만들지 않았다(UX Spec에 없음). 점수 숫자와 기준 문구를 나란히 두어 학습 판단에 필요한 정보만 보인다.
- 버튼을 전부 같은 모양으로 나열하지 않고 CTA·작은 주 버튼·보조 3단계로 위계를 준다.
- (엔진 정보 순서 검사) SCR-102는 승인 정보 순서(코트 → 질문 → 판정 → 진행·점수)에 맞춰 DOM을 본문 → 아래 영역 → 상단 바 순으로 두고 CSS grid 영역으로 상단 바를 위에 배치했다. 구현에서는 접근성을 위해 상단 바를 DOM 앞에 둬야 하므로 Preview·구현 단계 확인 항목으로 남긴다. 진행·점수 요소 표지(info-4)는 판정 상태 프레임부터 붙였다(같은 이유).

## 다른 시안과의 차이
- B는 아래 영역을 평면(구분선)으로, 판정을 상태색 띠로, ST10 재생 컨트롤을 4칸 도구 막대로, 상단 바에 상황 5칸 진행 띠를 두고, 결과 화면을 카드 없이 가운데 정렬 구획으로 나눈다. A는 시트·카드로 영역을 띄우고 왼쪽 정렬한다.
